# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

UMD (Universal Molecular Dynamics) is a Python package for post-processing ab initio and classical molecular dynamics simulations. It works around a central ASCII file format (`.umd.dat`) that stores atomic trajectories and thermodynamic data extracted from simulation codes (VASP, QBox, LAMMPS).

## Building C Extensions

Performance-critical routines are implemented as C shared libraries loaded at runtime via `ctypes`. They **must be compiled before running any analysis script**. All commands run from `src/`:

**macOS:**
```bash
gcc -dynamiclib -o c_UMDprocess.dylib c_UMDprocess.c
gcc -dynamiclib -o c_bonds_full.dylib c_bonds_full.c
gcc -dynamiclib -o c_clusters.dylib c_clusters.c
gcc -O2 -dynamiclib -o c_gofr.dylib c_gofr.c
```

**Linux / Windows (`.so` / `.dll`):** See `compilC-mac.txt` and `compilC-windows.txt` for the analogous commands.

`umd_processes_fast.py` auto-detects the OS and loads the correct library extension (`.dylib` / `.so` / `.dll`). The library path is resolved relative to the script's own `__file__` location, so scripts must be run from the `src/` directory or the libraries must be on the system path.

## Dependencies

```
python3, numpy, scipy, matplotlib
```

No package installation is required — scripts are run directly.

## Running Scripts

All scripts are standalone executables. Typical invocation pattern:
```bash
python3 src/VaspParser.py -f <OUTCAR_file> [-i InitialStep] [-s SkipStep]
python3 src/gofr_umd.py -f <file.umd.dat> [options]
python3 src/averages.py -f <file.umd.dat> [-p Pattern] [-s SkipSteps] [-l] [-v]
```

Use `-h` or read the argument-parsing block at the bottom of each script to discover its options.

## Architecture

### Core Libraries
- **`crystallography.py`** — Defines the two central data structures used everywhere:
  - `Atom`: position (`xred`, `xcart`, `absxcart`), velocities, forces, charge, magnetization
  - `Lattice`: simulation cell (vectors, volume, angles), atom list, and all thermodynamic scalars (energy, pressure, temperature, stress tensor, etc.). Also contains `Elements2rest()` (element → atomic number / mass lookup) and coordinate-transformation methods.
  - `Lattice.__init__`'s `acell`/`angles`/`rprim`/`rprimd`/`gprimd`/`stress` used to be mutable default arguments, so every `Lattice()` created without explicit values silently shared (and could corrupt) the same list — fixed to build a fresh list per instance. No script constructs `Lattice()`/`Atom()` with explicit keyword arguments, so this was a pure latent-bug fix.
- **`umd_processes_fast.py`** — Python wrapper around `c_UMDprocess.dylib` (ctypes). Provides fast reading of UMD snapshots and bond-definition routines used by most analysis scripts. This is the main I/O layer for `.umd.dat` files. It holds the only POSCAR routines of the package: `write_poscar(filename,title,cell,elements,counts,xred,vels=None)` (atoms grouped by element, direct coordinates, `Cartesian` velocities in Å/fs) and `read_poscar(filename)` (VASP5, reduced or Cartesian, selective dynamics, Cartesian velocities; returns title, cell, element per atom, xred, vels or None), used by `build_umd.py` and `umd2out.py`; `crystallography.Lattice.printcontcar` (unused, wrote typat as the atom counts) was removed.

### UMD File Format (`.umd.dat`)
Human-readable ASCII: one header section per snapshot followed by per-atom lines. Fields include `timestep`, `time`, `InternalEnergy`, `Enthalpy`, `Temperature`, `Pressure`, `StressTensor`, `acell`, `rprim`, and per-atom `xred`/`xcart`/`vels`/`forces`. Parsers write this format; analysis scripts read it.

### Parsers (simulation code → `.umd.dat`)
| Script | Source format |
|---|---|
| `VaspParser.py` | VASP OUTCAR |
| `QBoxParser.py` | QBox XML output |
| `LAMMPSParser2umd.py` | LAMMPS dump files |

`VaspParser.py` unwraps the positions (`absxcart`) at every MD step from `-i` on, even those not written with `-s`, so no crossing of a cell face is missed. It finds each crossing as a whole-number change of the displacement in reduced coordinates, which works for any cell shape. The `timestep` it writes is the time between written snapshots (`-s` × POTIM), as the analysis scripts expect. On-the-fly ML learning steps print the positions twice (ML and DFT blocks); the previous positions are taken only from the first block of each ionic step.

### Analysis Scripts
Each script imports `crystallography` and `umd_processes_fast`; most also load a dedicated C library for the heavy computation.

**Structural:**
- `gofr_umd.py` — pair distribution functions g(r) and running coordination numbers `Int(A-B)` of all element pairs, one method for every cell (uses `c_gofr`, compiled with -O2: ~25 % faster). The C routine takes the nearest image in reduced coordinates (ds − rint(ds)), exact up to half the smallest distance between opposite faces of the cell (V/|b×c| etc.), the largest r computed; it uses the cell of every snapshot (NPT; read from the rprimd lines, matched to read_values' -i/-s selection) and fills caller-allocated histograms over blocks of snapshots run in threads (ctypes releases the GIL). g is normalized with the volume of each snapshot and N_i(N_j − δ_ij) pairs, so it tends to 1; Int = cumulated pair counts / N_i, up to the outer edge of each bin. Output format unchanged (header parsed by `analyze_gofr.py`). It replaced `c_gofr_new_alt`, which wrapped the b direction with the a component in non-orthogonal cells, normalized with maxlength³ instead of the volume, took the largest r from vector lengths (and ignored c in orthogonal cells), used one cell for all snapshots, and ignored -k. Checks: ideal gas in a triclinic cell changing at every snapshot gives g = 1.000 ± 0.03; fcc in its cubic and its 60° primitive cell give the same 12 and 54 neighbours; hexagonal corundum equals a brute-force count over explicit images to 3e-14; cubic pyrolite equals the old code for unlike pairs (3e-13) and differs by N/(N−1) for like pairs; 0.9 s vs 4.2 s. `gofr_new_notcubic.py` and `c_gofr_new.c` (a never-compiled duplicate) were removed.
- `analyze_gofr.py` — first maximum, first minimum, coordination number and mean distance (∫r³g/∫r²g up to the minimum) of the first shell of every pair, from the gofr files of `gofr_umd.py`; automatic, `-v` to check and correct each pair in a plot. Merges the former `analyze_gofr.py` (clicks on every pair of every file), `analyze_gofr_semi_automatic.py` (clicks on the first file, guesses for the others) and `analyze_1gofr.py` (one file, mean distance), all removed. Method: g smoothed by a gaussian (`-g`, default 0.03 Å; 0.05 loses the small O-O peak at 2.5 Å of glycine); the first peak is the first one with g > 1 whose prominence exceeds 10× the local noise of the smoothed curve (MAD of the second differences over ±25 bins, robust to the curvature of sharp peaks; a residual-based rms was inflated near sharp peaks and hid the glycine O-O sub-peak); the minimum is the lowest point before the next prominent peak (any height: the N-H sub-peak at 1.68 Å of glycine, g 0.43, bounds its first minimum). Maximum: cubic fitted to g over the top quarter of the peak; minimum: parabola over the bottom tenth of the dip, else the middle of this region when it is flat (g = 0 between the shells of a molecule — any cutoff inside gives the same bonds; glycine C-C 2.36 Å instead of 1.665 Å before, 14924 vs 14920 C-C bonds over 1000 snapshots). Coordination = Int(A-B) interpolated at the minimum on the outer bin edges. A-B and B-A share positions, each its own coordination. Notes: `shallow minimum` (g(min) > 0.5 g(max)), `no pairs`, `no peak above the noise and above 1`, `no minimum up to rmax`. The noise of minority pairs (1–3 atoms of an element) is correlated between bins (slow configurations), so noise bumps of 5–20× the white-noise estimate occur there and their positions are unreliable (e.g. pyrolite Na-*, Al-Al): check them with `-v`. `-v`: Previous/Next over the pairs of all files, left click = maximum, right click = minimum (Snap: extremum of the smoothed g within 0.1 Å, refined as the automatic ones), Discard, Automatic; the files are written when the window is closed. Outputs (format `A B value`, read by `bonding_umd.py -i`; names unchanged): `<base>.maximum_bonds.inp` (first minima = bond cutoffs), `<base>.average_bonds.inp` (first maxima, as before, although the name says average; the mean distance is `rmean` in the summary), `<base>.coordinations.inp`, and `gofrs_summary.txt` per folder (`xmax ymax xmin coord`, as before, then `ymin rmean` per pair; nan without a shell; columns = union of the pairs of the folder). Default: every `*.gofr.dat` below the current folder; `-f` one file, `-a` pairs (others get 0, i.e. no bond), `-p` one png per pair. Checks: ZnS S-Zn 4.001, S-S 12.016, Zn-Zn 12.054; corundum Al-O 6.000, O-Al 4.000; glycine C-C 1.000, C-O 1.000, C-N 0.500 per C; melts Si-O 3.99–4.06, Al-O 4.16–4.19, H-O 1.025. Old windows of ±8–25 % (from a table of ionic radii) biased the maxima by up to 0.015 Å and put the glycine O-N minimum on the falling side of the peak (3.115 vs 3.408 Å).
- `bonding_umd.py` — bonds of every snapshot, from the cutoffs of `-i` (`A B cutoff`, e.g. `maximum_bonds.inp` of `analyze_gofr.py`) or one length `-l`, written to `<base>.bonding.dat` (per snapshot, one line per atom: the atom, then its bound atoms, each once, in increasing order; read by `speciation_and_angles.py`). `c_bonds_full` puts the atoms in sub-cells from their reduced coordinates and compares each atom with the atoms of the 27 surrounding sub-cells, each sub-cell visited once even with fewer than 3 sub-cells along a direction, and each pair once, in its nearest image (ds − rint(ds), as in `c_gofr`), for any cell. The number of sub-cells is set along each of a, b, c from the perpendicular widths of the cell (V/|b×c| etc.), so that a sub-cell is wider than the longest bond (`-n` sets it for all directions). The former code visited the same sub-cell several times when there were 2 per direction (cells narrower than 3 longest bonds: glycine, pyrolite, hydrous andesite), so neighbours were repeated up to 8 times: the clusters were unaffected, but `speciation_and_angles.py` counted every angle several times (glycine O-C-O: 7680 instead of 5000) and repeated bonds broke the bond lifetimes. In non-orthogonal cells it folded the b component when the a component exceeded 0.5, and sized the sub-cells from the lengths of a, b, c instead of their perpendicular widths: hexagonal corundum (`al2o3.new`) missed 16 % of its bonds. Checks: equal to a brute-force search over all pairs (nearest image) for glycine, corundum, hydrous andesite, pyrolite, ZnS, with `-l`, `-n 1` and `-p`; ZnS (3 sub-cells) is byte-identical to the former output; glycine speciation files are identical. Uses the cell of every snapshot (NPT; `umd_processes_fast.read_cells`), the sub-cells sized from the smallest widths over the run; a glycine trajectory deformed (stretch + shear) at every snapshot equals the brute-force search, the former code (first cell for all) missed 3704 and added 2004 bonds over 100 snapshots.
- `speciation_and_angles.py` — chemical species, angles and bond lifetimes from a `.bonding.dat` file (`-b`), for central (`-c`) and adjacent (`-a`) elements; the bonds are read once (`umd_processes_fast.read_bonds`). `-p 1` (default): clusters by `c_clusters` (`-r 1` central + bound adjacents, `-r 0` polymerization, `-r x` x-th coordination sphere), written to `<base>.r<r>.popul.dat` (each cluster: Begin/End in steps of the bonding file, lifetime in fs), `.stat.dat`, `.step.dat` (read by `msd_clusters_umd.py`, `liquid_and_vapor_speciation.py`, `lifetimes.py`, `stat-concentrate.py`); `-m` minimum lifetime (fs). The central and adjacent atoms in no cluster are species of their own (`H_1`, `O_1`…) in popul and stat for every `-r` (the C code returned them only with `-r 0`; with `-r` ≥ 1 they were only in the step file, so the stat percentages, and the vapor of `stat-concentrate.py`, left them out: glycine free H 14 % of the species time). The first header line ends with `timestep <dt> fs`, the time between two steps of the bonding file (the unit of Begin/End and of the steps of the step and angle files); the readers skip this line, `msd_clusters_umd.py` and `liquid_and_vapor_speciation.py` use it. `-t 1` (needs the UMD file `-f`): every angle adjacent–central–adjacent of every snapshot in `<base>.angles.dat` (any number of elements; per snapshot `mean` and `stdev` — the former `msd` column was sqrt(Σ(a−mean)²/mean)), and with `-r 1` the mean angles of each cluster in the popul and stat files. Angles from the two bond vectors, each the nearest image in reduced coordinates, with the cell of each snapshot (NPT; checked against an explicit 27-image search on a deformed trajectory, 2e-11°). The former code (Python for the angle file, C `angles` for the clusters, both removed) used the law of cosines with an independent minimum image per Cartesian component of the neighbour–neighbour distance: wrong when two neighbours are more than half a cell apart (glycine N–O at 3.4 Å: 924 of 1468 cluster rows changed, single angles by up to 98°), and in non-orthogonal cells (corundum O–Al–O: 56277 angles below 60°, mean 98.2° instead of 103.9°). `-l 1`: lifetimes of the central–adjacent bonds by pair of elements (each bond once, also when both atoms are central and adjacent), `<base>.bondslives.dat`, lifetime = snapshots × time step; the former version crashed (KeyError) when a central–central bond existed, skipped the atoms with a single bond, and was split by the repeated neighbours of the old `bonding_umd.py`. With `-s` > 1 the lifetimes of popul/stat were multiplied by `-s` twice and the angles read the wrong UMD snapshots (`-s` × the bonding/UMD ratio × `-s`). Output names: `<base>` = the UMD file if given, else the bonding file (formerly `<umd file>.angles.dat` and `<bonding file without .dat>.bondslives.dat`). `-p 0` now skips the species (formerly `-t 1` with one element each gave only the angles, and `-p 0 -t 1` gave the species with angles). Checks: glycine (r 0/1/2) and hydrous andesite (r 0/1) popul/stat/step byte-identical to before; glycine angle file identical to 1e-13°; bond lifetimes sum to the bond counts of the bonding file. `c_clusters`: counted the adjacent atoms with the number of central elements (out-of-bounds read when fewer adjacent than central elements).
- `lifetimes.py` — plot of the lifetime of every individual species of r1 popul files: one column per central element (from the `-c=` of the popul header, or `-c` for the vapor/liquid popul files of `liquid_and_vapor_speciation.py`, which have no header), one row per number of adjacent atoms x (MO_x; `-x xmin,xmax`), each panel the species sorted by decreasing lifetime (filled stairs) with their mean; panels with several formulas (several adjacent elements) labelled MX_x. The single atoms are in row 0, always shown (also with `-x`): the central ones in their column, the free adjacent atoms in columns of their own (`free H`…, only row 0); species with several central atoms left out. `-l <length>` splits the species into liquid and vapor with `liquid_and_vapor_speciation.split` (r0 step files `-s`, default `<prefix>.r0.step.dat` for each `<prefix>.r<r>.popul.dat`): `<popul base>.liquid.lifetimes.pdf` and `.vapor.lifetimes.pdf`, both with the same columns and rows. One `<popul base>.lifetimes.pdf` per file (default every `*.r1.popul.dat` of the folder), `-m` merges the files (independent runs at the same P and T) into one figure (`-o`; with `-l` `<output>.liquid.pdf`, `.vapor.pdf`), `-t` minimum lifetime, `-v` window with Previous/Next. Colours: the reference categorical palette in fixed order, one per element (central, then adjacent elements of the header). Replaced a first version (pairs of `*.outcar.umd.dat` and popul files, lifetimes vs pressure) that never ran (the help/exit block was outside its `if`) and skipped the first two species of each popul file.
- `liquid_and_vapor_speciation.py` — splits the species of a popul file (typically r1) into liquid and vapor, from an r0 step file of the same bonding file: an atom is vapor at a step when its r0 cluster has fewer than `-l` atoms (default 12), a species is liquid when one of its atoms is; writes `<popul base>.vapor.popul.dat`, `.vapor.stat.dat`, `.liquid.popul.dat`, `.liquid.stat.dat`. Steps of the popul file every `-s` of its header (it stops when a step is missing from the step file), lifetimes = snapshots × `-s` × timestep (popul header, else the step file). `split(populfile,stepfile,length)` returns the vapor and liquid species (used by `lifetimes.py -l`). Formerly a notebook export that crashed with speciation `-s` > 1 (KeyError) and whose `-l` was reset to 12 unless it was the last option; same outputs for `-s 1` (glycine with 1.6 Å bonds: vapor 20.8 %; vapor + liquid time = popul time, also with `-s 2`: 21.4 %).

**Transport:**
- `msd_umd.py` — mean-square displacements per element (`-m elements`) or per atom and element (`-m atoms`), written to `<base>.msd.dat` (`#` comment lines, then a `time_(fs)` column header). Computed in numpy with the FFT algorithm (Calandrini/nMoldyn), averaged over all time origins, for lags up to half the trajectory; this replaced the former `c_msd` C library (removed), which took ~100x more CPU time and only used origins from the first half. `-a cart` / `-a cryst` (`Auto` is a synonym) / `-a [x1,y1,z1,...]` add the MSD projected on unit vectors along x,y,z / the a,b,c vectors of the first snapshot's cell / arbitrary axes, as extra columns `El_x`, `El_a`, `El_1`… For a non-orthogonal cell the a,b,c components do not sum to the total. `-b` drops lags shorter than the ballistic regime, `-v` writes every v-th lag, `-z` is accepted but ignored (kept because `UMD_GUI.py` and `MSDdistrib.py` pass it). It also fits D (slope/6 total, slope/2 per axis; `analyze_msd.calculation_diffusivities` is imported, so both tools share one fit) between `-b` and `-e` (default 0.75 of the last lag of a block, i.e. 7.5 % of the trajectory for 5 blocks; with `-n` 0/1 the 5-block length is used; fitting to long lags made D ~3× noisier in random-walk tests) and writes `<base>.diffusion.dat` (D, error, R², alpha, with a warning when alpha is outside 0.9–1.1). Errors come from `-n` consecutive blocks (default 5; MSDs written to `<base>.msd.blocks.dat`, which `analyze_msd.py` also uses): error = std(D_blocks)·√(t_end,full / (n·t_end,block)), because the variance of a fitted D grows with the fit-window end and falls with trajectory length. The plain std/√n would underestimate it 2–3× when the full fit is longer than the blocks. Calibrated on synthetic random walks (reported/actual scatter 0.83–1.08); the linear-regression slope error is ~200× too small. `main()` returns `[msdfile, MSD, Instants, elements, Axes]` with `MSD[species][0]` the total and `MSD[species][1+k]` axis k, normalized per atom; `UMD_GUI.py` and `MSDdistrib.py` rely on this. `msd_all_umd.py` was an older pure-Python duplicate and has been removed.
- `msd_clusters_umd.py` — MSD of the mass-weighted centre of mass of each cluster listed in a `.popul.dat` file from `speciation_and_angles.py`, one `<popul base>__<cluster>.msd.dat` file per cluster type (popul base = the popul file without `.popul.dat`, e.g. `glycine.r1__C_1H_1.msd.dat`) (one column per cluster instance, plus their mean). Reuses `msd_umd.msd_fft`. The popul Begin/End steps (steps of the bonding file) are converted to UMD snapshots with the `timestep` of the popul header, or for older popul files from the lifetime column — which was wrong for short lives with speciation `-s` > 1 (glycine `-s 2`: ratio 20 found for 26 of 1136 clusters, 40 for 557).
- `viscosity_umd.py` — shear viscosity by Green–Kubo from the UMD `StressTensor`; the only viscosity tool (the viscosity modes of `spectra_umd.py` and `spectra_umd_corrected.py` were removed). By default uses the 5 independent components of the traceless stress tensor N = σ − pI (Daivis–Evans weights: 1/5 per off-diagonal, 2/15 per diagonal, the diagonal running integrals ×3/4); `-c offdiag` uses only xy, yz, zx. The mean of the whole run is removed once (blocks included), and η(t) is corrected for the bias this causes: η = η_raw/(1 − 2 t_end/T_run). FFT autocorrelation, cumulative trapezoid integral. η is read at the end of the integral, `-e` (steps; default and max = half a block, 1/8 of the run with the default `-n 4` blocks); the error is the standard error over the blocks. A warning flags η(t) still rising by > 2 errors over the second half (not converged → lower bound). Automatic windows (Sokal) and the double-exponential time-decomposition fit (Zhang–Otani–Maginn) were tried and rejected: melts have a small but long stress-autocorrelation tail that Sokal cuts (hydrous andesite: 2.0 vs ~5.5 mPa·s), and the fit was unstable with a few blocks. Synthetic tests (known η): unbiased within noise, error ~0.7–0.85 of the real scatter. `-i` skips initial snapshots, `-v` plots autocorrelations and running viscosities. Output `<base>.visc.dat`.
- `analyze_msd.py` — fits all element/atom `*.msd.dat` files (from `msd_umd.py`) below the current folder and writes one `diffusivities.txt` per folder. Cluster MSD files are recognized by their `cl0 … mean` header and skipped. Columns: `file`, `fit_start(fs)`, `fit_end(fs)`, `error` (blocks/fit), then 6 per species (D, D_stdev, R², slope, intercept, alpha). The species columns are the union over all files of the folder, `nan` where a file lacks one. D = slope/6 for total-MSD columns, slope/2 for single-axis columns (any name containing `_`). Fit window `-s` to `-e` in fs (default end 0.75 of the last block time if a blocks file exists, else 0.15 of the last MSD time — the same point as for 5 blocks). D_stdev is the block error when `<base>.msd.blocks.dat` exists, otherwise the (underestimated) regression error. alpha is the log-log slope of the MSD over the window (MSD ~ t^alpha): a warning is printed outside 0.9–1.1 (sub-diffusive / ballistic). `-v` shows each MSD with its fit and shaded window, with Previous/Next buttons (`plot_fits`, matplotlib imported lazily so `msd_umd.py`, which imports this module, does not need it).
- `analyze_msd_clusters.py` — the same for the cluster MSD files of `msd_clusters_umd.py`, one `diffusivities_clusters.txt` per folder (one row per cluster file: instances, instances used, window, D, error, R², slope, intercept, alpha). Instances live for different times, so only those living through the whole fit window are averaged and fitted; default end = 0.75 of the median instance lifetime; error = std of the per-instance D / √n. Short-lived species often stay ballistic (alpha ≈ 2) — check alpha. Reuses the fit, alpha and plot functions of `analyze_msd.py`; `-v` as there.

**Thermodynamic:**
- `averages.py` — mean and stdev of any numerical field of UMD files (`-f`, several separated by commas; default every `*.umd.dat` of the folder). Default: Pressure, Temperature and InternalEnergy on one tab-separated line per file (`file #PstdTstdEstd nsteps P stdev_P T stdev_T E stdev_E`, a format that may be parsed by downstream scripts — keep it stable). `-p <Pattern>` averages a single field instead; multi-valued fields (`StressTensor`, `acell`, …) are averaged component by component. `-l` gives the long per-component output (mean, variance, stdev, error of the mean, unit), `-v` opens a plot with Previous/Next buttons stepping through the quantities/components one at a time, each on its own y-scale (default: no display). `-i` and `-s` are synonyms for the number of initial snapshots to skip (default 0 = all). `averages_detailed.py` and `averages_visual.py` were merged into it and removed; `averages_forGUI.py` is a separate copy kept only because `UMD_GUI.py` imports it. `-a` (all the thermodynamics) = the former `fullaverages.py` (removed): `fullthermo.dat` with the header lines `elements`/`number` (of the first file; warning when another file differs), then per file nsteps, density, P, T, E per atom (mean, stdev, error of the mean) and Cv in N kB with its error; `-u 1` adds T in eV, E per cell and in J/g, Cv in J/K/mol (of atoms), J/K/g and J/K per cell (same columns as before, more digits). E = potential + kinetic energy of the ions: `VaspParser.py` has added `KineticEnergyIons` into `InternalEnergy` since 2024 (glycine, al2o3, pyrolite, ZnS), older files did not (hydrous andesite), detected per file from `TotalElectronicEnergy` + `KineticEnergyIons` = `InternalEnergy` when written, else from cov(InternalEnergy, KE)/var(KE) (1 or 0: potential and kinetic energies are uncorrelated in NVT). `fullaverages.py` always added the KE, so E was 3/2 kT per atom too high and Cv 4.5 N kB too high for current files (ZnS at 1000 K 22.7 N kB, corundum 9.5). Cv = ⟨δU²⟩/(kB T²) + 3/2 N kB (canonical; U = potential energy; NVT only, warning when the cell changes); the former bootstrap error ignored the correlation of the snapshots. Errors of the mean from the integrated autocorrelation time (`vibrations_umd.mean_error`, which now also returns tau): the former blocking selection compared σ with ±1/√(2(n−1)) (a relative error used as absolute, so unit-dependent) and gave errors 3–10× too small on correlated series (AR(1) tests, tau ≥ 10); the new error is 0.99–1.01 of the true scatter, 0.86–1.05 for Cv, `>` (lower bound) with fewer than 50 independent samples (n/2tau; the error is then ~10–35 % low). Constant series (NVT density): error 0. Warnings: a quarter of the run deviating by > 4 errors of a block mean (drift; glycine P and E; ≤ 1/400 false alarms on stationary series), and kinetic-energy fluctuations off the canonical 3/2 N kB² T² by > 25 % (ZnS 1.59, Cv 14.5 ± 3.4 N kB, quarters 34/9.6/8.0/5.6: not reliable; the others 1.12–1.18, Nosé oscillations). The former version also always skipped the first snapshot, used e = 1.6e-19 J, and wrote E/atom with 3 digits.
- `vdos_thermo.py` — harmonic thermodynamics from the vDOS of `vibrations_umd.py` (reads `<base>.vibr.err.dat`, else `<base>.vibr.dat` without errors; atom counts from the UMD header; each element renormalized to 3 N_El modes): per atom and per element, quantum ZPE, E, F, S, Cv, and the quantum corrections dE, dF, dS, dCv = quantum − classical harmonic (Berens et al. 1983), to add to classical MD values; `-t T1,T2,…` (default: the vDOS temperature; the MD frequencies are kept). The first frequency interval is integrated with the small-x expansions (S and F diverge as ln ν). Errors propagated from the vDOS band, taken independent on a grid of one FWHM (~0.3–1 %). Warns when g(0) > 2 % of the peak (diffusive modes): the harmonic S and F of a liquid are then not meaningful, the corrections and Cv are. Liquid entropy: 2PT (Lin, Blanco, Goddard 2003) at the vDOS temperature (needs masses and the mean cell volume, read from the UMD file; `<base>.2pt.dat`): Δ from g(0), fluidicity f by brentq, gas-like Lorentzian with the same g(0) (3fN modes) + hard-sphere (Carnahan–Starling) entropy, solid-like = rest with the quantum HO weight. Each element is its own 2PT system with partial density N_El/V (ideal mixing via V/(fN_El); cross-correlations neglected — an approximation for mixtures). The Lorentzian (1/ν²) exceeds the vDOS at high ν, making the solid-like vDOS negative (column `negative`, 0.3–2 %): negligible for the quantum S_2PT, but it gave wrong-sign classical S_2PT and solid-part quantum corrections, so these were removed; dE etc. come from the whole vDOS. Checks: ideal-gas limit gives Sackur–Tetrode (20.523 vs 20.516 kB); corundum f = 0 → harmonic S; Lennard-Jones liquid argon (numpy MD, 256 atoms, 87.3 K, 1.395 g/cm³, written as UMD and run through vibrations_umd.py) gives 56.2 J/(mol K) vs ~55.6 experimental; pyrolite 9.94 and hydrous andesite 9.24 kB/atom at 3000 K (f 0.12–0.28, y up to 0.56). Checks: Einstein and Debye models reproduce the analytic Cv, S, E, ZPE to ≤ 0.02 %; corundum (al2o3.new) at 1500 K: S 231 J/(mol K) per Al2O3, Cv 122; hydrous andesite at 3000 K: H has ZPE 279 meV and dE 57 meV per atom (1.8 eV per cell). Output `<base>.vdos.thermo.dat`.
- `vibrations_umd.py` — velocity autocorrelation functions (VACF), vibrational densities of states (vDOS) and diffusion coefficients from the UMD velocities, per element and, with `-a cart` / `-a cryst` / `-a [x1,y1,z1,...]` (as in `msd_umd.py`), per element along each axis (not per atom). The only vibration tool: it replaced `vibr_spectrum_umd_fast.py` (its C library `c_autocorrelation_vib`, O(N²), took ~10x more CPU time), `spectra_umd.py` (broken with current scipy) and `spectra_umd_corrected.py`, all removed. VACFs by FFT over all time origins. vDOS = 2 m/(kB T) × the cosine transform of the VACF, mass-weighted, in states per cm⁻¹ (the old script wrote per fs⁻¹ against a cm⁻¹ axis), so the vDOS of an element integrates to 3 N_El · T_kin/T (N_El per axis). T is the mean `Temperature` of the UMD file (`-t` overrides it; the old default was 5000 K); the kinetic temperature of the velocities is also printed. With `-i 0` the first snapshot is dropped when its ⟨v²⟩ is 0 or more than 10× from the median of the next 100: the parsers have no previous step there (current `VaspParser.py` writes 0; older versions wrote the positions, as in the pyrolite and glycine test files, which gave a spike at t=0 in the VACF and a flat vDOS up to Nyquist). `-w` is the VACF length used for the spectra (steps, default half a block, max half the run), `-p hann` (default) / `none` a one-sided Hann taper applied to all spectra (suppresses truncation ringing), `-g` a Gaussian smoothing in cm⁻¹ (reflection at 0, exact for an even spectrum), zero-padding ×4 for a finer frequency grid. D (Green–Kubo) is the running integral 1/3∫⟨v(0)·v(t)⟩ (∫⟨v_k v_k⟩ per axis), read at `-e` (steps; default and max half a block), with the standard error over `-n` blocks (default 4, min 3), and a warning when D changes by > 2 errors between half the integral and its end (solids: D oscillates around 0, which the block error does not include). Checks: the MSD of `msd_umd.py` equals 2∫∫VACF within 1 % up to 1 ps on the hydrous andesite; synthetic OU velocities give unbiased D with error/scatter 0.98–1.03; synthetic oscillators give the right peaks and exact normalization. D from the VACF and from the MSD fit differ when the system is not yet diffusive over the windows (they use different times). Outputs: `<base>.vels.scf.dat` (normalized VACFs, mass-weighted `Average`, running `D_El`), `<base>.vibr.dat` (one header line `Frequency(cm^-1)`, `VDos_El`…, `Total_DOS`, the format read by `UMD_GUI.py`; keep it), `<base>.vibr.axes.dat` (with `-a`), `<base>.vacf.diffusion.dat`. `-v` plots the VACFs and vDOS with their error band (the running D is in `<base>.vels.scf.dat`). vDOS errors (`<base>.vibr.err.dat`: each vDOS, also along axes, followed by `_err`; `main` returns them last): spread of the vDOS of min(`-n`, run/window) blocks at least one window long, scaled to the whole run by the variance of a Blackman–Tukey spectrum on the unbiased VACF, 1/L + Σ_{t≥1} w(t)²/(L−t) (lag t has variance ~1/(L−t)); an earlier L·Σw²/(L−t)² overweighted the long lags of short blocks and gave errors ~0.8× too small, and 20× too small without taper. With Hann the relative variance var/g² is averaged over the FWHM (~24000/T cm⁻¹, printed), without taper the variance itself. Checks: synthetic Gaussian velocities give error/scatter median 0.92–1.03, 0.55–0.75 at the top of peaks whose lifetime (~1 ps) is comparable to the blocks; real-data halves test std(z) 0.9–1.2 for pyrolite and hydrous andesite, ~1.8 for ZnS at 1000 K (long-lived phonons), 1.7 for glycine (not stationary: ⟨v²⟩ rises 26 % over the run while its `Temperature` field stays 300.0). Three checks are printed in the terminal (`check_zero_velocities`, `check_temperatures`, `check_halves`): (0) snapshots whose velocities are all exactly 0, the signature of `VaspParser.py` before 48975f1 on on-the-fly ML learning steps (`data/al2o3.umd.dat`, hexagonal corundum + 1 He: 151 such snapshots, 4.5 % of block 1, which made block 1 ~60 K colder and triggered the drift warning; its absxcart is also wrong, from the missed crossings and the old acell/2 test in a hexagonal cell — re-parse the OUTCAR or use `repair_umd.py`; `data/al2o3.new.umd.dat` is the re-parsed version); (1) the kinetic temperature of each element per `-n` block and over the run, with an error from the integrated autocorrelation time of the linearly detrended series (`mean_error`; without detrending a drift inflates τ and hides itself: glycine H τ 676 → 6 steps); warnings for a block deviating by > 4 block errors (drift) and for an element differing from all atoms by > 4 errors (no equipartition). Glycine: O 408→312 K and H 227→297 K over the run while the total stays ~301 K (the earlier "⟨v²⟩ rises 26 %" was the unweighted mean, dominated by H); ZnS: S 968 K vs Zn 1024 K (±4), steady. Melts pass (max 2.2 block, 3.2 equipartition). (2) the vDOS of the two halves, same window, each with its block errors: rms(diff)/rms(√(e₁²+e₂²)) per element and total, warning above 1.5 for the total (melts 0.86–0.96; glycine 1.6, ZnS 2.3 with `-n 4` and only 2.1 with `-n 3`, so fewer blocks do not fix crystals: the `-n` help says to scale the band by this ratio; pyrolite with `-p none` 1.7); skipped when the window exceeds 1/4 of the run. Non-orthogonal cell check on al2o3 with `-a cryst`: the equivalent a and b axes give the same vDOS (Al integrals 92.8/94.5, mean frequency 550/546 cm⁻¹), c differs (518 cm⁻¹); halves ratio 1.19. `UMD_GUI.py` calls `main(["-f", file])`, plus `-t` only when its temperature field is filled.

**Utilities:**
- `umd2out.py` — convert UMD snapshots to XYZ or POSCAR (`-r 2`: one `<name>._<step>_.POSCAR.vasp` per snapshot, by `umd_processes_fast.write_poscar`, with the cell of each snapshot — formerly the first cell for all, wrong for NPT — and the velocities)
- `build_umd.py` — builds new structures (`<name>[.<snapshot>].build<k>.umd.dat`, `.POSCAR`, `.xyz`; `-o`, default umd,poscar) from a snapshot of a UMD file (`-f -i`, default the last; `-s` every s-th), a VASP5 POSCAR (element line; Cartesian velocities read) or an empty box (`-a`), by operations applied in command-line order, each repeatable: `--supercell na,nb,nc`, `--shuffle n|na,nb,nc|<size>A`, `--insert <molecules file>`, `--scale f|fa,fb,fc`, `--density ρ`, `--replace A:B[:n|:x]`, `--remove formula[:n]`; then Maxwell–Boltzmann velocities at `-t` (default 1500 K) for the atoms without velocities (inserted, POSCAR without velocities, empty box; `--velocities all` for all): no net momentum of the drawn atoms, kinetic temperature exactly T with 3(n−1) degrees of freedom (900 atoms: T 1500.000 K, ⟨v²⟩/(kT/m) 1.007 and 0.984 for O and He). `-n` structures per input, `--seed`. Merges `build_supercell.py`, `box_shuffle.py` and `insert_umd.py` (removed). One `Structure` (cell, element per atom, xred, velocities, whether each atom has a velocity, masses of the UMD header or `Elements2rest`) for all operations, any cell shape; atoms grouped by element on output in order of first appearance. UMD output: one snapshot (positions, velocities, cell, density, kinetic temperature; other fields 0) via `umd_processes_fast.print_header/print_snapshots`; POSCAR: direct coordinates and `Cartesian` velocities (Å/fs). Supercell: equals `build_supercell.py` to 3e-11, velocities repeated. Scale: lengths of the cell (reduced coordinates and velocities kept, so bonds scale too); prints the density and the shortest distance. Shuffle: the cell is cut into sub-cells along a, b, c in reduced coordinates (congruent for any cell shape) and permuted with atoms and velocities. AIMD sub-cells are a few bond lengths wide, so every permutation brings atoms close at the interfaces (glycine, pyrolite 3×3×3 or 2×2×2: shortest distances 0.25–0.6 of normal, 25–40 % of the atoms involved). Of `--tries` permutations (default 100) the least overlapping is kept (it favours permutations that move fewer interfaces; `--tries 1` = plain random), permutations that only translate the structure by sub-cells (identity, rigid shifts, swaps of identical copies after `--supercell`) are rejected, then pairs closer than `-d` (default 1.5 Å, absolute, user's choice; or `-c` × the shortest distance of their pair of elements before the shuffle — large for rare elements, pyrolite Ca–Ca 7.8 Å) are pushed apart along the line joining them, the lighter atom more (m_other/(m_i+m_j)), nearest images; no pair is pushed beyond its own distance before the shuffle, so bonds inside the sub-cells are kept (hydrous andesite O–H down to 0.89 Å) and only contacts made by the shuffle move. A warning lists the element pairs whose shortest distance fell below 0.8 × that before the shuffle (with 1 Å, pyrolite kept Si–O 1.00, Si–Si 1.20, Mg–O 1.08 Å; with the 1.5 Å default, 15 atoms pushed, rms 0.17 Å, cation–cation and O–O contacts at 1.5 Å remain listed) — choose `-d` or `-c` for the system. `-c 0.9` reproduces the fixed `box_shuffle.py` for the same seed. Replace: all the atoms of A, n random ones, or a fraction x (decimal point); velocities × √(m_A/m_B), keeping each atom's kinetic energy. Remove: whole molecules of a formula (`H2O`, `C2H5NO2`, `O` = free O atoms; also `H_2O_1`), all or n random ones; a molecule = a connected component of the bond graph (nearest images) with exactly this composition, bonds from `-l` (one length) or `-b` (lines `A B cutoff`, e.g. `maximum_bonds.inp`; absent pairs: no bond); it stops when fewer are found. Glycine: one 1.6 Å length joins molecules by H bonds (3 of 10 found), per-pair cutoffs find 10 of 10 in the first snapshot, 6 and 4 later (proton transfers: 9- and 11-atom molecules). Checks: inserting 4 H₂O into pyrolite then `--remove H2O -l 1.2` gives back the original POSCAR exactly. Insert: `molecules.dat` format of `insert_umd.py` (`ntime`, `natom`, `element x y z`; `data/molecules.dat`), random reduced position, uniform random orientation (`Rotation.random`) about the centre of mass, no atom closer than `-r` (default 2.0 Å, user's choice) to any other, nearest images, any cell. Checks: intramolecular distances kept to 3e-15 Å in cubic and hexagonal boxes, intermolecular ≥ `-r`, orientations uniform (400 dimers), the snapshot's atoms and velocities unchanged. Former scripts: `box_shuffle.py` imported the removed `umd_process` (could not run), checked distances without periodic images in a cubic cell of side a, retried by reshuffling shuffled positions with no limit and a 0.5 Å threshold, truncated coordinates (`'%.7s' % str(x)`); `insert_umd.py` only handled orthogonal cells (acell), drew rotation axes in the positive octant only (non-uniform orientations), rotated about the first atom, dropped the velocities of the snapshot, gave the new atoms none, named outputs `struct-<n>`; `build_supercell.py` dropped velocities and wrote str() precision.
- `stat-concentrate.py` — concentrates the statistics of independent runs at the same P and T: all the `*.r0.stat.dat` of the current folder (r0 only — the liquid and the vapor are told apart by the size of the r0 clusters, `-l`), one column per run, with the mole and mass liquid/vapor partitioning of the elements of `-c`; the output name records the options (`<-f>all.-t<t>.-L<l>.-R0.-C=<c>.dat`, keep it). `-t`: species whose total time in a run is shorter than t fs are left out of that run (it was read but not used). Unused `relativespecies` removed; outputs unchanged with the defaults.
- `check_overlap.py` — detect atomic overlaps
- `crystallography.py` also contains `Elements2rest()`, used widely for element → mass/atomic-number lookup

### Data Flow
```
OUTCAR / QBox / LAMMPS dump
        ↓  Parser scripts
    <name>.umd.dat
        ↓  Analysis scripts (read via umd_processes_fast / C libs)
    <name>.gofr.dat / .bonding.dat / .msd.dat / .vibr.dat / …
        ↓  Analyze/plot scripts
    summary files + matplotlib figures
```

## Naming Conventions
Output files inherit the UMD filename as prefix: `<base>.umd.dat` → `<base>.gofr.dat`, `<base>.bonding.dat`, `<base>.r0.popul.dat`, etc. Test data in `data/` follows this convention with `glycine.*` files.
