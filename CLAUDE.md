# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

UMD (Universal Molecular Dynamics) is a Python package for post-processing ab initio and classical molecular dynamics simulations. It works around a central ASCII file format (`.umd.dat`) that stores atomic trajectories and thermodynamic data extracted from simulation codes (VASP, QBox, LAMMPS).

## Building C Extensions

Performance-critical routines are implemented as C shared libraries loaded at runtime via `ctypes`. They **must be compiled before running any analysis script**. All commands run from `src/`:

**macOS:**
```bash
gcc -O2 -dynamiclib -o c_UMDprocess.dylib c_UMDprocess.c
gcc -dynamiclib -o c_bonds_full.dylib c_bonds_full.c
gcc -dynamiclib -o c_clusters.dylib c_clusters.c
gcc -O2 -dynamiclib -o c_gofr.dylib c_gofr.c
```

**Linux / Windows (`.so` / `.dll`):** See `compilC-mac.txt` and `compilC-windows.txt` for the analogous commands.

`umd_processes_fast.py` auto-detects the OS and loads the correct library extension (`.dylib` / `.so` / `.dll`). The library path is resolved relative to the script's own `__file__` location, so scripts must be run from the `src/` directory or the libraries must be on the system path.

## Dependencies

```
python3, numpy, scipy, matplotlib
```

No package installation is required — scripts are run directly.

## Running Scripts

All scripts are standalone executables. Typical invocation pattern:
```bash
python3 src/VaspParser.py -f <OUTCAR_file> [-i InitialStep] [-s SkipStep]
python3 src/gofr_umd.py -f <file.umd.dat> [options]
python3 src/averages.py -f <file.umd.dat> [-p Pattern] [-s SkipSteps] [-l] [-v]
```

Use `-h` or read the argument-parsing block at the bottom of each script to discover its options.

## Architecture

### Core Libraries
- **`crystallography.py`** — Defines the two central data structures used everywhere:
  - `Atom`: position (`xred`, `xcart`, `absxcart`), velocities, forces, charge, magnetization
  - `Lattice`: simulation cell (vectors, volume, angles), atom list, and all thermodynamic scalars (energy, pressure, temperature, stress tensor, etc.). Also contains `Elements2rest()` (element → name, symbol, atomic number, mass; None if unknown), `Elements2charge()` (formal charge: the most common oxidation state in oxides and ionic compounds, field `formalcharge` of the table, used by `check_umd.py`) and coordinate-transformation methods: `xred2xcart`/`xcart2xred`/`absxcart2xred` (wrapped into [0,1)) and their `all…` versions over the atoms, xcart = xred @ rprimd with rprimd as it is (rows a, b, c), and `makegprimd` = inverse(rprimd) transposed (xred[i] = Σ_j gprimd[i][j] xcart[j]; `VaspParser.py`, `repair_umd.py`). The conversions summed `rprimd[ii][jj]*xred[ii]` (wrong index: right only for cubic cells; 3.4 Å off in a hexagonal cell) after rebuilding rprimd from acell·rprim; only `QBoxParser.py` used them, so QBox runs in non-cubic cells had wrong coordinates. `makegprimd` printed an error and did not divide by the determinant for left-handed cells (now any handedness; outputs of `VaspParser.py` on ZnS and `repair_umd.py` on hexagonal corundum byte-identical to before). Removed: `compangles`, `printstruct`, `niceprint` (called a missing `cartlatt`), `TripleLattice` (missing `cartatom`), `derive_types_from_typat`, `distance`, `CheckAtoms` (unused). `getdensity` uses the exact Avogadro constant.
  - `Lattice.__init__`'s `acell`/`angles`/`rprim`/`rprimd`/`gprimd`/`stress` used to be mutable default arguments, so every `Lattice()` created without explicit values silently shared (and could corrupt) the same list — fixed to build a fresh list per instance. No script constructs `Lattice()`/`Atom()` with explicit keyword arguments, so this was a pure latent-bug fix.
- **`umd_processes_fast.py`** — Python wrapper around `c_UMDprocess.dylib` (ctypes). Provides fast reading of UMD snapshots and bond-definition routines used by most analysis scripts. This is the main I/O layer for `.umd.dat` files. It holds the only POSCAR routines of the package, and the shared readers/writers `read_snapshots(UMDfile,natom,first,sampling,fields,atoms)` (line by line, any file size: yields the fields of every snapshot and the atom array — reduced, cartesian, unwrapped, velocity, force, charge, magnetization — of every sampling-th from first; used by `check_umd.py` and `umd2out.py`), `run_on_all(argv,main,paired,single)` (`-f all`: the script's `main` once per `*.umd.dat` of the current folder, sorted, with `-f <file>`; `paired` options taken per file from its base — speciation `-b <base>.bonding.dat`, msd_clusters `-p <base>.r1.popul.dat` —, `single` options refused — `-o` of umd2out and repair_umd —; `SystemExit` and exceptions of one file caught, the next file goes on, the failed ones listed; `headerumd` prints the banner once per process; outputs identical to separate runs, checked on glycine, pyrolite and a 1-snapshot file for check, gofr, bonding, speciation, msd, msd_clusters, viscosity, vibrations, vdos_thermo, umd2out; `averages.py`, `thermo_integration_umd.py`, `umd_workflow.py` take `-f all` as their default), `cell_of(fields)` (rprimd, else acell) and `xyz_frame` (one extended XYZ frame, used by `umd2out.py` and `build_umd.py`). POSCAR: `write_poscar(filename,title,cell,elements,counts,xred,vels=None)` (atoms grouped by element, direct coordinates, `Cartesian` velocities in Å/fs) and `read_poscar(filename)` (VASP5, reduced or Cartesian, selective dynamics, Cartesian velocities; returns title, cell, element per atom, xred, vels or None), used by `build_umd.py` and `umd2out.py`; `crystallography.Lattice.printcontcar` (unused, wrote typat as the atom counts) was removed. `read_values(UMDfile,key,mode,Nsteps,firststep,laststep)` (key xred, xcart, absxcart, velocity, or everything = these 12 columns; snapshots firststep, firststep+Nsteps, … before laststep) reads in one pass in C (`c_UMDprocess.c`: `umd_read`, numbers by strtod) into a numpy array (snapshot, values; `lists` (snapshot, atom, column), `chunks` column after column); `count_snapshots` gives the complete snapshots (a last snapshot cut short, by a run still being written, is left out with a warning) and `read_cells` the cell of each snapshot (rprimd, else acell) from the same C reader. Values identical to the former reader on glycine, ZnS, hydrous andesite, corundum (the files have 5 decimals, which the former reader rounded to); 3–6× faster without child processes (hydrous andesite 468 MB: 0.9 s vs 2.7 s and 9 CPU s in 16 processes), 2.5–3× less memory (compile it with -O2: 1.5× faster). The former reader ran one process per snapshot with a hand-written number parser: `E` exponents, tabs and repeated or leading blanks gave wrong values silently (up to 11 Å), a truncated last snapshot was read as zeros, and it failed when run from standard input (process pool). With Nsteps > 1 it read int(n/Nsteps) snapshots, missing the last one (glycine `-s 3` from 5: 3331 instead of 3332); now all, also in `read_bonds` (bonding files). `Crystallization` (header, also `no.of.electrons` and `lambda_ThermoInt`, and the cell of the first snapshot; stops at the first snapshot, also of a bonding file, which it formerly read to the end) replaces `read_bigheader_umd`; its unused `WithLength` option (time of the last snapshot parsed byte by byte) was removed. `read_stresses_4visc` uses `read_snapshots`. `defineBonds` (C, bonding files) allocated (N_central+N_adjacent)² integers per snapshot (400 MB for 10000 atoms) and its result was never freed. `print_header`/`print_snapshots` (all parsers, `build_umd.py`, `repair_umd.py`) build one string per snapshot (output byte-identical). The library path is built with `os.path` (formerly split on `/`, which fails on Windows).

### UMD File Format (`.umd.dat`)
Human-readable ASCII: one header section per snapshot followed by per-atom lines. Fields include `timestep`, `time`, `InternalEnergy`, `Enthalpy`, `Temperature`, `Pressure`, `StressTensor`, `acell`, `rprim`, and per-atom `xred`/`xcart`/`vels`/`forces`. Parsers write this format; analysis scripts read it.

**Rule: no update or new feature may change the format in a way that breaks the reading of UMD files, by the current or by former versions of the package.** New information goes into new lines that every reader skips: never the first line (old readers take it as `natom`), never between the `atoms:` line and the atom lines, and with no field name as a separate word (`averages.py` greps the fields anywhere in the file).

The header ends with `origin <code> : <sentence>` (`umd_processes_fast.print_header(…,origin)`, read into `Lattice.origin` by `Crystallization`), the code that produced the run: `VaspParser.py` writes `origin VASP : the UMD file originated from a VASP ab initio molecular dynamics simulation`, `LAMMPSParser2umd.py` `origin LAMMPS : …`, `build_umd.py` `origin build_umd.py : the UMD file is a structure built by build_umd.py, <title>`; copied by `build_umd.py --extract`, `repair_umd.py` and into the bonding files. Files written before have no origin line. Checked: the readers of the current and of the former version (before fad7cee) give identical outputs with and without the line.

### Parsers (simulation code → `.umd.dat`)
| Script | Source format |
|---|---|
| `VaspParser.py` | VASP OUTCAR |
| `QBoxParser.py` | QBox XML output |
| `LAMMPSParser2umd.py` | LAMMPS dump files (custom/atom or xyz) and log |

`VaspParser.py` unwraps the positions (`absxcart`) at every MD step from `-i` on, even those not written with `-s`, so no crossing of a cell face is missed. It finds each crossing as a whole-number change of the displacement in reduced coordinates, which works for any cell shape. The `timestep` it writes is the time between written snapshots (`-s` × POTIM), as the analysis scripts expect. On-the-fly ML learning steps print the positions twice (ML and DFT blocks); the previous positions are taken only from the first block of each ionic step. `TotalElectronicEnergy` = the free energy TOTEN of the `% ion-electron` line, divided by SCALEE (λ, thermodynamic integration), as in the parser before the ML rewrite (cbc0495, January 2026), which had dropped it (0.0 written in every snapshot since; glycine predates it). So InternalEnergy = TotalElectronicEnergy + ElectronicEntropy (= E0 − TOTEN) + KineticEnergyIons (λ = 1). Checked on the ZnS OUTCAR (ML_ISTART=1, 10000 steps, 57 of them with a DFT calculation): TotalElectronicEnergy = TOTEN in all 10000 steps, the relation within 1e-6 eV, the rest of the UMD file identical to before.

`LAMMPSParser2umd.py` (rewritten; options `-f` dump, `-l` log, `-a` stress file kept for `UMD_GUI.py`, output `<dump>.umd.dat`; `-o`, `-u` metal/real, `-t` timestep in fs, `-e` elements per type, `-i`/`-s`): dump custom/atom text files (columns id, type, element, x/xs, xu/xsu, ix iy iz, vx vy vz, fx fy fz, q, in any order; orthogonal, restricted triclinic `xy xz yz` and general triclinic `abc origin` boxes, the box of every frame, any origin) or dump xyz (box from the log). Atoms sorted by id (MPI dumps are not), grouped by element (by id within). Unwrapped positions from xu/xsu, else image flags, else followed between frames (nearest move in reduced coordinates). Log: units, timestep, mass, `dump_modify element`, `pair_coeff * * … <elements>` (else element from the mass), box, thermo output of every run (`one`/`custom` header rows, also between warnings; `multi` blocks), matched to the frames by step (the old parser read one thermo row per frame, wrong when thermo and dump intervals differ). Fields: InternalEnergy = TotEng (potential + kinetic, as `VaspParser.py`), TotalElectronicEnergy = PotEng (so `averages.kinetic_included` sees the kinetic energy), KineticEnergyIons = KinEng, EnergyWithDrift = Econserve or TotEng, Enthalpy, Temperature, Pressure, StressTensor from Pxx Pyy Pzz Pxy Pyz Pxz (or `-a`: `step pxx pyy pzz pxy pxz pyz`); without them KE and T (3N−3) from the velocities. Units converted (metal: ps, Å/ps, bar; real: kcal/mol, atm) to fs, Å/fs, eV, eV/Å, GPa; time from `ITEM: TIME` or step × timestep (rounded to 1e-6 fs); timestep field = time between written snapshots. The former version wrote `Internal Energy` (unread by every script), took acellx for the three cell vectors, handled orthogonal boxes only (x/acell, fmod), kept the velocities in Å/ps (1000× too large), swapped the xz and yz stress components of `-a`, ignored NPT boxes, and wrote no masses. Checks (synthetic dumps and logs written from glycine and hexagonal corundum UMD runs through `umd2out.lammps_atoms`): positions, unwrapped positions, velocities, forces, energies, T, P, stress, cell equal the expected values to the rounding of the files, for image flags, xu, xs (followed), xsu, shuffled ids, non-zero origin, a cell deformed at every frame, `units real`, `thermo_style multi` with `-a`, dump xyz; ~14 s for a 125 MB dump (the writing, `print_snapshots`, takes 2/3).

### Analysis Scripts
Each script imports `crystallography` and `umd_processes_fast`; most also load a dedicated C library for the heavy computation.

**Structural:**
- `gofr_umd.py` — pair distribution functions g(r) and running coordination numbers `Int(A-B)` of all element pairs, one method for every cell (uses `c_gofr`, compiled with -O2: ~25 % faster). The C routine takes the nearest image in reduced coordinates (ds − rint(ds)), exact up to half the smallest distance between opposite faces of the cell (V/|b×c| etc.), the largest r computed; it uses the cell of every snapshot (NPT; read from the rprimd lines, matched to read_values' -i/-s selection) and fills caller-allocated histograms over blocks of snapshots run in threads (ctypes releases the GIL). g is normalized with the volume of each snapshot and N_i(N_j − δ_ij) pairs, so it tends to 1; `-c` central / `-a` adjacent elements (commas, default `all`): the pairs central–adjacent and their reverse are computed (as `analyze_gofr.py -c/-a`; `-c O` = O-X and X-O for every X), only the atoms of these elements in the computation; all the pairs of the UMD file are written, in its order, the others with g = 0 and Int = 0, so `analyze_gofr.py` writes them with 0 (no bond) in complete `.inp` files (it writes every pair of the elements of the gofr file, also for a file of 2.8.2 with only the selected columns: then the pairs of its elements only) and leaves them out of its plots (the user's choice, 2026-10-26; in 2.8.2 the file had only the central–adjacent columns); output `<base>.<central>-<adjacent>.gofr.dat` (symbols concatenated, `all` when not given, e.g. `.SiMg-O.`, `.O-all.`; without `-c`/`-a` `<base>.gofr.dat` as before, byte-identical); `bonding_umd.py` with the resulting cutoffs bonds only those pairs (pyrolite `-c Si,Mg -a O`: Mg-O and Si-O bonds only); columns identical to those of the full file (same `-k`: the threads sum in a different order otherwise, last digit), `analyze_gofr.py` gives the same cutoffs and coordinations (pyrolite Si-O, Mg-O); Int = cumulated pair counts / N_i, up to the outer edge of each bin. Output format unchanged (header parsed by `analyze_gofr.py`). It replaced `c_gofr_new_alt`, which wrapped the b direction with the a component in non-orthogonal cells, normalized with maxlength³ instead of the volume, took the largest r from vector lengths (and ignored c in orthogonal cells), used one cell for all snapshots, and ignored -k. Checks: ideal gas in a triclinic cell changing at every snapshot gives g = 1.000 ± 0.03; fcc in its cubic and its 60° primitive cell give the same 12 and 54 neighbours; hexagonal corundum equals a brute-force count over explicit images to 3e-14; cubic pyrolite equals the old code for unlike pairs (3e-13) and differs by N/(N−1) for like pairs; 0.9 s vs 4.2 s. `gofr_new_notcubic.py` and `c_gofr_new.c` (a never-compiled duplicate) were removed.
- `analyze_gofr.py` — first maximum, first minimum, coordination number and mean distance (∫r³g/∫r²g up to the minimum) of the first shell of every pair, from the gofr files of `gofr_umd.py`; automatic, `-v` to check and correct each pair in a plot. Merges the former `analyze_gofr.py` (clicks on every pair of every file), `analyze_gofr_semi_automatic.py` (clicks on the first file, guesses for the others) and `analyze_1gofr.py` (one file, mean distance), all removed. Method: g smoothed by a gaussian (`-g`, default 0.03 Å; 0.05 loses the small O-O peak at 2.5 Å of glycine); the first peak is the first one with g > 1 whose prominence exceeds 10× the local noise of the smoothed curve (MAD of the second differences over ±25 bins, robust to the curvature of sharp peaks; a residual-based rms was inflated near sharp peaks and hid the glycine O-O sub-peak); the minimum is the lowest point before the next prominent peak (any height: the N-H sub-peak at 1.68 Å of glycine, g 0.43, bounds its first minimum). Maximum: cubic fitted to g over the top quarter of the peak; minimum: cubic over the bottom tenth of the dip (`MAX_FIT`: both fits at most 1 Å wide, ±0.5 Å around the extremum of the smoothed g; the user's choice), else the lowest point of the smoothed g when the cubic has no minimum inside; when g = 0 at the minimum (between the shells of a molecule) the middle of the run of g = 0 bins (any cutoff inside gives the same bonds; glycine C-C 2.320 Å, gap 1.705–2.935 Å; 1.665 Å in the first version, 14924 vs 14920 C-C bonds over 1000 snapshots). Until 2026-10-26 the minimum was a parabola over the whole bottom tenth (up to 2.1 Å wide), biased toward the slow side of asymmetric dips: pyrolite Al-O 2.721 Å vs 2.575 for the lowest point of the smoothed g (now 2.600), Mg-O 3.035/2.965 (2.979), Si-O 2.599/2.475 (2.420, a flat dip), hydrous andesite H-O 1.392/1.475 (1.511), glycine N-H 1.433/1.335 (1.351); coordinations Si-O 4.056 → 4.004, Al-O 4.185 → 4.087, Mg-O 5.076 → 4.929, H-O 1.025 → 1.058; the maxima are unchanged (their windows are 0.06–0.7 Å). Coordination = Int(A-B) interpolated at the minimum on the outer bin edges. A-B and B-A share positions, each its own coordination. Terminal table: printed once (after the checks with `-v`), one line per pair A-B with the coordination numbers of A-B and B-A, the pairs not analyzed or without pairs on one line. Notes: `shallow minimum` (g(min) > 0.5 g(max)), `no pairs`, `no peak above the noise and above 1`, `no minimum up to rmax`. The noise of minority pairs (1–3 atoms of an element) is correlated between bins (slow configurations), so noise bumps of 5–20× the white-noise estimate occur there and their positions are unreliable (e.g. pyrolite Na-*, Al-Al): check them with `-v`. `-v`: buttons Discard, Automatic, Manual input, All manual, Previous, Next (one pass over the pairs of all files, each pair once — A-B and B-A share the g(r) and change together —; Next on the last pair closes the window and writes the files, Previous on the first stays; no wrap-around); two left clicks, the maximum then the minimum (the right click of the former version, for the minimum, did not reach matplotlib on Mac trackpads); Manual input (default): from each click up (down) the smoothed g to the top of its peak (bottom of its dip), then the fits of the automatic analysis (cubic over the top quarter, parabola over the bottom tenth), so a click on an automatic shell gives its values back (pyrolite: exactly for the main pairs, ≤ 0.03 Å for noisy minority pairs, where a click lands on a neighbouring wiggle); All manual: the clicked points as they are (maximum height = clicked height); a minimum before the maximum is refused; the files are written when the window is closed. Tested with simulated mouse events (Agg). The former Snap on/off toggle is replaced by Manual input/All manual. Outputs (format `A B value`, read by `bonding_umd.py -c`; names unchanged): `<base>.maximum_bonds.inp` (first minima = bond cutoffs), `<base>.average_bonds.inp` (first maxima, as before, although the name says average; the mean distance is `rmean` in the summary), `<base>.coordinations.inp`, and `gofrs_summary.txt` per folder (`xmax ymax xmin coord`, as before, then `ymin rmean` per pair; nan without a shell; columns = union of the pairs of the folder). Default: every `*.gofr.dat` below the current folder; `-f` one file, `-c` central / `-a` adjacent elements (as `gofr_umd.py`; the pairs central–adjacent and their reverse, e.g. `-c Si,Mg -a O`: Si-O, Mg-O, O-Si, O-Mg; `-c O`: O-X and X-O), `-a` with pairs (`-a Si-O,Mg-O`, an argument with `-`: the former use, still accepted) (others get 0, i.e. no bond; outputs identical to the former `-a` pairs for the same pairs, pyrolite), `-p` one png per pair. Checks: ZnS S-Zn 4.001, S-S 12.016, Zn-Zn 12.054; corundum Al-O 6.000, O-Al 4.000; glycine C-C 1.000, C-O 1.000, C-N 0.500 per C; melts Si-O 3.99–4.06, Al-O 4.16–4.19, H-O 1.025. Old windows of ±8–25 % (from a table of ionic radii) biased the maxima by up to 0.015 Å and put the glycine O-N minimum on the falling side of the peak (3.115 vs 3.408 Å).
- `bonding_umd.py` — bonds of every snapshot, from the cutoffs of `-c` (formerly `-i`, still accepted with a file name; `A B cutoff`, e.g. `maximum_bonds.inp` of `analyze_gofr.py`) or one length `-l`, written to `<base>.bonding.dat` (per snapshot, one line per atom: the atom, then its bound atoms, each once, in increasing order; read by `speciation_and_angles.py`). `c_bonds_full` puts the atoms in sub-cells from their reduced coordinates and compares each atom with the atoms of the 27 surrounding sub-cells, each sub-cell visited once even with fewer than 3 sub-cells along a direction, and each pair once, in its nearest image (ds − rint(ds), as in `c_gofr`), for any cell. The number of sub-cells is set along each of a, b, c from the perpendicular widths of the cell (V/|b×c| etc.), so that a sub-cell is wider than the longest bond (`-n` sets it for all directions). The former code visited the same sub-cell several times when there were 2 per direction (cells narrower than 3 longest bonds: glycine, pyrolite, hydrous andesite), so neighbours were repeated up to 8 times: the clusters were unaffected, but `speciation_and_angles.py` counted every angle several times (glycine O-C-O: 7680 instead of 5000) and repeated bonds broke the bond lifetimes. In non-orthogonal cells it folded the b component when the a component exceeded 0.5, and sized the sub-cells from the lengths of a, b, c instead of their perpendicular widths: hexagonal corundum (`al2o3.new`) missed 16 % of its bonds. Checks: equal to a brute-force search over all pairs (nearest image) for glycine, corundum, hydrous andesite, pyrolite, ZnS, with `-l`, `-n 1` and `-p`; ZnS (3 sub-cells) is byte-identical to the former output; glycine speciation files are identical. Uses the cell of every snapshot (NPT; `umd_processes_fast.read_cells`), the sub-cells sized from the smallest widths over the run; a glycine trajectory deformed (stretch + shear) at every snapshot equals the brute-force search, the former code (first cell for all) missed 3704 and added 2004 bonds over 100 snapshots. `-i` (2026-10-26): first snapshot used; the bonding file then has a header line `first_snapshot i : …` (`umd_processes_fast.copyhead(…,first)`, read into `Lattice.firstsnapshot` by `Crystallization`; the bonding reader keys on lines beginning with `step`, old readers skip it), times written from the start of the UMD file; `speciation_and_angles.py` reads the UMD snapshots of the angles from it and writes ` first_snapshot i` at the end of the popul/stat/step header line, `msd_clusters_umd.py` adds it to the popul steps. Checks (glycine, `-i 1000`): bonds, popul/stat/step/angles/bondslives and the cluster MSDs identical to those of the old scripts on the run trimmed by `build_umd.py --extract 0-99 -i 1000`; default outputs byte-identical; the old speciation reads the new bonding file.
- `speciation_and_angles.py` — chemical species, angles and bond lifetimes from a `.bonding.dat` file (`-b`), for central (`-c`) and adjacent (`-a`) elements; the bonds are read once (`umd_processes_fast.read_bonds`). `-p 1` (default): clusters by `c_clusters` (`-r 1` central + bound adjacents, `-r 0` polymerization, `-r x` x-th coordination sphere), written to `<base>.r<r>.popul.dat` (each cluster: Begin/End in steps of the bonding file, lifetime in fs), `.stat.dat`, `.step.dat` (read by `msd_clusters_umd.py`, `liquid_and_vapor_speciation.py`, `lifetimes.py`, `stat-concentrate.py`); `-m` minimum lifetime (fs). The central and adjacent atoms in no cluster are species of their own (`H_1`, `O_1`…) in popul and stat for every `-r` (the C code returned them only with `-r 0`; with `-r` ≥ 1 they were only in the step file, so the stat percentages, and the vapor of `stat-concentrate.py`, left them out: glycine free H 14 % of the species time). The first header line ends with `timestep <dt> fs`, the time between two steps of the bonding file (the unit of Begin/End and of the steps of the step and angle files); the readers skip this line, `msd_clusters_umd.py` and `liquid_and_vapor_speciation.py` use it. `-t 1` (needs the UMD file `-f`): every angle adjacent–central–adjacent of every snapshot in `<base>.angles.dat` (any number of elements; per snapshot `mean` and `stdev` — the former `msd` column was sqrt(Σ(a−mean)²/mean)), and with `-r 1` the mean angles of each cluster in the popul and stat files. Angles from the two bond vectors, each the nearest image in reduced coordinates, with the cell of each snapshot (NPT; checked against an explicit 27-image search on a deformed trajectory, 2e-11°). The former code (Python for the angle file, C `angles` for the clusters, both removed) used the law of cosines with an independent minimum image per Cartesian component of the neighbour–neighbour distance: wrong when two neighbours are more than half a cell apart (glycine N–O at 3.4 Å: 924 of 1468 cluster rows changed, single angles by up to 98°), and in non-orthogonal cells (corundum O–Al–O: 56277 angles below 60°, mean 98.2° instead of 103.9°). `-l 1`: lifetimes of the central–adjacent bonds by pair of elements (each bond once, also when both atoms are central and adjacent), `<base>.bondslives.dat`, lifetime = snapshots × time step; the former version crashed (KeyError) when a central–central bond existed, skipped the atoms with a single bond, and was split by the repeated neighbours of the old `bonding_umd.py`. With `-s` > 1 the lifetimes of popul/stat were multiplied by `-s` twice and the angles read the wrong UMD snapshots (`-s` × the bonding/UMD ratio × `-s`). Output names: `<base>` = the UMD file if given, else the bonding file (formerly `<umd file>.angles.dat` and `<bonding file without .dat>.bondslives.dat`). `-p 0` now skips the species (formerly `-t 1` with one element each gave only the angles, and `-p 0 -t 1` gave the species with angles). - `msd_umd.py` — mean-square displacements per element (`-m elements`) or per atom and element (`-m atoms`), written to `<base>.msd.dat` (`#` comment lines, then a `time_(fs)` column header). Errors come from `-n` consecutive blocks (default 5; MSDs written to `<base>.msd.blocks.dat`, which `analyze_msd.py` also uses): error = std(D_blocks)·√(t_end,full / (n·t_end,block)), because the variance of a fitted D grows with the fit-window end and falls with trajectory length. The plain std/√n would underestimate it 2–3× when the full fit is longer than the blocks. Calibrated on synthetic random walks (reported/actual scatter 0.83–1.08); the linear-regression slope error is ~200× too small. `main()` returns `[msdfile, MSD, Instants, elements, Axes]` with `MSD[species][0]` the total and `MSD[species][1+k]` axis k, normalized per atom; `UMD_GUI.py` relies on this. `-a tensor`: the components xx, yy, zz, xy, yz, zx of the MSD tensor ⟨Δr_i Δr_j⟩, from the MSDs along x, y, z and the diagonals (i+j)/√2 (⟨Δu²⟩ = (⟨Δi²⟩+⟨Δj²⟩)/2 + ⟨Δi Δj⟩), each fitted as 2 D_ij t (blocks as for the axes; no alpha for the off-diagonal terms), and `<base>.diffusion.tensor.dat`: per element the tensor with errors, the isotropic D (trace/3, equal to the D of the total MSD), the principal values D1 ≥ D2 ≥ D3 with errors (spread of the principal values of the block tensors, scaled as `block_diffusivity_error`) and directions, D1/D3; `-p [a1,a2,a3,b1,b2,b3]` adds D(θ) = n·D·n every 5° in the plane of the two vectors (orthonormalized). Replaces `MSDdistrib.py` (removed; GUI only), which built directions cos θ A1 + sin θ A2 (uneven angles unless A1 ⊥ A2 and equal lengths), averaged MSD/t over all lags (ballistic and noisy long lags included, not D) and only returned the values to the GUI. Checks: synthetic anisotropic random walks (200 atoms, 4000 steps, principal values 2, 1, 0.5 × 10⁻⁹ m²/s along rotated axes) recover 2.04, 0.99, 0.51 and the directions; over 4 trajectories rms((estimate − true)/error) 0.93 for the principal values, 1.31 for the components (one 4.6: 5-block errors are uncertain by ~35 %), 0.64 for the isotropic D; xx, yy, zz equal `-a cart` x, y, z exactly (pyrolite). Noise makes D1 > D3 even for isotropic systems (eigenvalue repulsion; pyrolite Si 7.1/6.5/6.0 ± 0.6): compare D1 − D3 with the errors. `msd_all_umd.py` was an older pure-Python duplicate and has been removed. `-i` first snapshot, `-s` sampling (time step × s; `-v`, `-b`, `-e` count the snapshots used): identical to the old script on the trimmed file (glycine `-i 1000`, `-i 1000 -s 2`).
- `msd_clusters_umd.py` — MSD of the mass-weighted centre of mass of each cluster listed in a `.popul.dat` file from `speciation_and_angles.py`, one `<popul base>__<cluster>.msd.dat` file per cluster type (popul base = the popul file without `.popul.dat`, e.g. `glycine.r1__C_1H_1.msd.dat`) (one column per cluster instance, plus their mean). - `viscosity_umd.py` — shear viscosity by Green–Kubo from the UMD `StressTensor`; the only viscosity tool (the viscosity modes of `spectra_umd.py` and `spectra_umd_corrected.py` were removed). By default uses the 5 independent components of the traceless stress tensor N = σ − pI (Daivis–Evans weights: 1/5 per off-diagonal, 2/15 per diagonal, the diagonal running integrals ×3/4); `-c offdiag` uses only xy, yz, zx. Outputs (tab-separated, `#` lines with the run and the result, then one row of column names, for ProFit/Origin): `<base>.stress.scf.dat` — the autocorrelation of each component of N (GPa²), `acf_mean` their weighted mean (diagonal ×3/4; its running integral × V/kBT is η before the bias correction), and the same normalized to 1 at t = 0 (`norm_…`), as `vibrations_umd.py` writes the VACFs to `<base>.vels.scf.dat` — and `<base>.visc.dat` — the running viscosity of each component, `eta`, `eta_err` (formerly one `.visc.dat` with the autocorrelations too; values unchanged).

- `analyze_msd_clusters.py` — the same for the cluster MSD files of `msd_clusters_umd.py`, one `diffusivities_clusters.txt` per folder (one row per cluster file: instances, instances used, window, D, error, R², slope, intercept, alpha). - `thermo_integration_umd.py` — free energy and entropy by thermodynamic integration from the ideal gas to the ab initio system (VASP SCALEE = λ): F = F_ideal gas + ∫₀¹⟨U⟩_λ dλ, S = (E − F)/T. One UMD file per λ (`-f`, default every `*.umd.dat` of the folder; `lambda_ThermoInt` of the header, U = `TotalElectronicEnergy` = TOTEN/SCALEE written by `VaspParser.py` — 0 in files parsed between cbc0495 and 9b74913, which the script refuses). ⟨U⟩_λ diverges as λ → 0, so the integral is over x = 2λ^(1−k) − 1 (`-k`, default 0.8; Dorner, Sukurma, Dellago, Kresse 2018), integrand ⟨U⟩λ^k/(2(1−k)), 0 at x = −1: Gauss–Legendre quadrature when the λ < 1 (or all λ) are its nodes λ = ((x+1)/2)^(1/(1−k)) (the VASP-wiki recipe), else a cubic spline through (−1, 0) and the points; the trapezoid value is printed as a check. F_ideal gas = −kT Σ_el [N ln(V/Λ³) − ln N!] with the cell volume (det), exact constants; T = `-t` (the thermostat temperature is best) or the mean Temperature of all runs; E = ⟨InternalEnergy⟩ of the λ = 1 run, kinetic energy included (`averages.kinetic_included`). Warnings: drift of ⟨U⟩, fewer than 50 independent samples, volumes or temperatures differing between runs (temperatures by > 4 errors + 0.2 %), no λ = 1 run, smallest λ far from 0. Checks (synthetic runs, atoms in harmonic wells in a periodic box: ⟨U⟩_λ and F exact; 8 atoms of 2 elements, 4000 correlated snapshots per λ): every ⟨U⟩ within its error; 10 Gauss–Legendre nodes give the integral −490.697 ± 0.073 eV (exact −490.673) and S 6.12 ± 0.08 kB/atom (exact 6.07 with the 3N−3 kinetic degrees of freedom of the synthetic runs; the ideal gas counts 3N, a difference of 1.5/N kB/atom); errors calibrated over 5 seeds, rms z 0.79. Quadrature error alone (exact ⟨U⟩, k = 0.8): Gauss–Legendre 0.47, 0.24, 0.018, 0.009 eV for 4, 6, 8, 10 nodes, the spline 1.1, 0.38, 0.067, 0.012 eV, the trapezoid 10–30 eV: use ≥ 8 nodes (the help says so).
- `vdos_thermo.py` — harmonic thermodynamics from the vDOS of `vibrations_umd.py` (reads `<base>.vibr.err.dat`, else `<base>.vibr.dat` without errors; atom counts from the UMD header; each element renormalized to 3 N_El modes): per atom and per element, quantum ZPE, E, F, S, Cv, and the quantum corrections dE, dF, dS, dCv = quantum − classical harmonic (Berens et al. 1983), to add to classical MD values; `-t T1,T2,…` (default: the vDOS temperature; the MD frequencies are kept). Warns when g(0) > 2 % of the peak (diffusive modes): the harmonic S and F of a liquid are then not meaningful, the corrections and Cv are. The Lorentzian (1/ν²) exceeds the vDOS at high ν, making the solid-like vDOS negative (column `negative`, 0.3–2 %): negligible for the quantum S_2PT, but it gave wrong-sign classical S_2PT and solid-part quantum corrections, so these were removed; dE etc. come from the whole vDOS. Checks: Einstein and Debye models reproduce the analytic Cv, S, E, ZPE to ≤ 0.02 %; corundum (al2o3.new) at 1500 K: S 231 J/(mol K) per Al2O3, Cv 122; hydrous andesite at 3000 K: H has ZPE 279 meV and dE 57 meV per atom (1.8 eV per cell). - `vibrations_umd.py` — velocity autocorrelation functions (VACF), vibrational densities of states (vDOS) and diffusion coefficients from the UMD velocities, per element and, with `-a cart` / `-a cryst` / `-a [x1,y1,z1,...]` (as in `msd_umd.py`), per element along each axis (not per atom). The only vibration tool: it replaced `vibr_spectrum_umd_fast.py` (its C library `c_autocorrelation_vib`, O(N²), took ~10x more CPU time), `spectra_umd.py` (broken with current scipy) and `spectra_umd_corrected.py`, all removed. T is the mean `Temperature` of the UMD file (`-t` overrides it; the old default was 5000 K); the kinetic temperature of the velocities is also printed. With `-i 0` the first snapshot is dropped when its ⟨v²⟩ is 0 or more than 10× from the median of the next 100: the parsers have no previous step there (current `VaspParser.py` writes 0; older versions wrote the positions, as in the pyrolite and glycine test files, which gave a spike at t=0 in the VACF and a flat vDOS up to Nyquist). `-w` is the VACF length used for the spectra (steps, default half a block, max half the run), `-p hann` (default) / `none` a one-sided Hann taper applied to all spectra (suppresses truncation ringing), `-g` a Gaussian smoothing in cm⁻¹ (reflection at 0, exact for an even spectrum), zero-padding ×4 for a finer frequency grid. D (Green–Kubo) is the running integral 1/3∫⟨v(0)·v(t)⟩ (∫⟨v_k v_k⟩ per axis), read at `-e` (steps; default and max half a block), with the standard error over `-n` blocks (default 4, min 3), and a warning when D changes by > 2 errors between half the integral and its end (solids: D oscillates around 0, which the block error does not include). Checks: the MSD of `msd_umd.py` equals 2∫∫VACF within 1 % up to 1 ps on the hydrous andesite; synthetic OU velocities give unbiased D with error/scatter 0.98–1.03; synthetic oscillators give the right peaks and exact normalization. D from the VACF and from the MSD fit differ when the system is not yet diffusive over the windows (they use different times). Outputs: `<base>.vels.scf.dat` (normalized VACFs, mass-weighted `Average`, running `D_El`), `<base>.vibr.dat` (one header line `Frequency(cm^-1)`, `VDos_El`…, `Total_DOS`, the format read by `UMD_GUI.py`; keep it), `<base>.vibr.axes.dat` (with `-a`), `<base>.vacf.diffusion.dat`. `-v` plots the VACFs and vDOS with their error band (the running D is in `<base>.vels.scf.dat`). vDOS errors (`<base>.vibr.err.dat`: each vDOS, also along axes, followed by `_err`; `main` returns them last): spread of the vDOS of min(`-n`, run/window) blocks at least one window long, scaled to the whole run by the variance of a Blackman–Tukey spectrum on the unbiased VACF, 1/L + Σ_{t≥1} w(t)²/(L−t) (lag t has variance ~1/(L−t)); an earlier L·Σw²/(L−t)² overweighted the long lags of short blocks and gave errors ~0.8× too small, and 20× too small without taper. **Utilities:**
- `umd2out.py` — converts UMD snapshots (every `-s`-th from `-i`, or `-k` one) to other formats, `-r` numbers or names separated by commas, all from one line-by-line read (`umd_processes_fast.read_snapshots`; glycine 10000 snapshots in 1 s, hydrous andesite 468 MB in 2 s): 1 `xyz` extended XYZ trajectory `<name>.xyz` (cell as `Lattice`, species, positions — wrapped, `-u` unwrapped — and forces; time, temperature, energy and stress (ASE sign: negative in compression, eV/Å³) in the comment line; formerly plain XYZ without the cell); 2 `poscar` one `<name>._<snapshot>_.POSCAR.vasp` per snapshot by `umd_processes_fast.write_poscar` (cell of each snapshot, velocities; identical to before); 3 `lammps` one `<name>._<snapshot>_.lammps.data` per snapshot (atom_style atomic, units metal, Masses, image flags from the unwrapped positions, Velocities in Å/ps); 4 `deepmd` DeepMD training set `<name>.deepmd/` (deepmd/npy: type.raw, type_map.raw, set.000… of 5000 frames with box, coord, energy, force, virial); 5 `lammpstrj` LAMMPS dump trajectory (`id type element x y z ix iy iz vx vy vz fx fy fz`, ITEM: TIME in ps). `-o` output name (default: the UMD file without `.umd.dat`; formerly ignored, and the names were cut with `[:-7]`); the former `-r 3`/`-r 4` wrote nothing. LAMMPS: restricted triclinic box (`lammps_box`: a along x, b in the xy plane; c → −c for a left-handed cell; tilts reduced to at most half a box length by adding lattice vectors — hexagonal corundum has xy/lx = −0.50000000005, rejected by LAMMPS otherwise), positions, velocities and forces rotated. DeepMD/XYZ energy = the free energy the forces derive from: InternalEnergy − KineticEnergyIons (when included, `averages.kinetic_included` over all snapshots) − ElectronicEntropy (VASP TOTEN); virial = V × (StressTensor − m v v/V) in eV, the UMD stress being VASP `Total+kin.` (kinetic part included): m v v from the UMD velocities scaled to 2 KineticEnergyIons, isotropic 2/3 KineticEnergyIons when the velocities are zero or off by > 2 (first snapshot of the parsers). The UMD file does not tell on-the-fly ML steps from DFT steps (train on the ML_AB file). Checks: ASE reads the XYZ, data and dump files and dpdata the DeepMD set, equal to the UMD positions, nearest-image and unwrapped distances, speeds, forces, energies to rounding, for glycine (cubic, and the same lattice in a skewed and a left-handed basis) and hexagonal corundum; ZnS against dpdata reading the OUTCAR: energies 5e-7 eV, forces 5e-6 eV/Å, virial/V vs the OUTCAR `in kB` stress within 0.011 GPa (kinetic part ~0.9 GPa), 0.06 GPa for the first snapshot (no velocities). `VaspParser.py` wrote `TotalElectronicEnergy` 0.0 from the ML rewrite (cbc0495) to its fix; umd2out then uses the correlation test.
- `build_umd.py` — builds new structures (`<name>[.<snapshot>].build<k>.umd.dat`, `.POSCAR`, `.xyz` (extended XYZ with the cell, `umd_processes_fast.xyz_frame`); `-o`, default umd,poscar) from a snapshot of a UMD file (`-f -i`, default the last; `-s` every s-th), a VASP5 POSCAR (element line; Cartesian velocities read) or an empty box (`-a`), by operations applied in command-line order, each repeatable: `--supercell na,nb,nc`, `--shuffle n|na,nb,nc|<size>A`, `--insert <molecules file>`, `--scale f|fa,fb,fc`, `--density ρ`, `--replace A:B[:n|:x]`, `--remove formula[:n]`; then Maxwell–Boltzmann velocities at `-t` (default 1500 K) for the atoms without velocities (inserted, POSCAR without velocities, empty box; `--velocities all` for all): no net momentum of the drawn atoms, kinetic temperature exactly T with 3(n−1) degrees of freedom (900 atoms: T 1500.000 K, ⟨v²⟩/(kT/m) 1.007 and 0.984 for O and He). Until 2026-10-25 the amu·Å²/fs² → eV constant was 1.0364269e-4 instead of 103.64 (`vibrations_umd.AMU_A2FS2`, now imported), so the drawn velocities were 1000× too large and the kinetic energy/temperature written in the UMD output were wrong; checked now against real velocities (glycine at 300 K: redrawn C 0.0045 vs 0.0042 Å/fs, written KineticEnergyIons 3.714 vs 3.738 eV in the file). `-n` structures per input, `--seed`. Merges `build_supercell.py`, `box_shuffle.py` and `insert_umd.py` (removed). One `Structure` (cell, element per atom, xred, velocities, whether each atom has a velocity, masses of the UMD header or `Elements2rest`) for all operations, any cell shape; atoms grouped by element on output in order of first appearance. UMD output: one snapshot (positions, velocities, cell, density, kinetic temperature; other fields 0) via `umd_processes_fast.print_header/print_snapshots`; POSCAR: direct coordinates and `Cartesian` velocities (Å/fs). Supercell: equals `build_supercell.py` to 3e-11, velocities repeated. Scale: lengths of the cell (reduced coordinates and velocities kept, so bonds scale too); prints the density and the shortest distance. Shuffle: the cell is cut into sub-cells along a, b, c in reduced coordinates (congruent for any cell shape) and permuted with atoms and velocities. AIMD sub-cells are a few bond lengths wide, so every permutation brings atoms close at the interfaces (glycine, pyrolite 3×3×3 or 2×2×2: shortest distances 0.25–0.6 of normal, 25–40 % of the atoms involved). Of `--tries` permutations (default 100) the least overlapping is kept (it favours permutations that move fewer interfaces; `--tries 1` = plain random), permutations that only translate the structure by sub-cells (identity, rigid shifts, swaps of identical copies after `--supercell`) are rejected, then pairs closer than `-d` (default 1.5 Å, absolute, user's choice; or `-c` × the shortest distance of their pair of elements before the shuffle — large for rare elements, pyrolite Ca–Ca 7.8 Å) are pushed apart along the line joining them, the lighter atom more (m_other/(m_i+m_j)), nearest images; no pair is pushed beyond its own distance before the shuffle, so bonds inside the sub-cells are kept (hydrous andesite O–H down to 0.89 Å) and only contacts made by the shuffle move. A warning lists the element pairs whose shortest distance fell below 0.8 × that before the shuffle (with 1 Å, pyrolite kept Si–O 1.00, Si–Si 1.20, Mg–O 1.08 Å; with the 1.5 Å default, 15 atoms pushed, rms 0.17 Å, cation–cation and O–O contacts at 1.5 Å remain listed) — choose `-d` or `-c` for the system. `-c 0.9` reproduces the fixed `box_shuffle.py` for the same seed. Replace: all the atoms of A, n random ones, or a fraction x (decimal point); velocities × √(m_A/m_B), keeping each atom's kinetic energy. Remove: whole molecules of a formula (`H2O`, `C2H5NO2`, `O` = free O atoms; also `H_2O_1`), all or n random ones; a molecule = a connected component of the bond graph (nearest images) with exactly this composition, bonds from `-l` (one length) or `-b` (lines `A B cutoff`, e.g. `maximum_bonds.inp`; absent pairs: no bond); it stops when fewer are found. Glycine: one 1.6 Å length joins molecules by H bonds (3 of 10 found), per-pair cutoffs find 10 of 10 in the first snapshot, 6 and 4 later (proton transfers: 9- and 11-atom molecules). Checks: inserting 4 H₂O into pyrolite then `--remove H2O -l 1.2` gives back the original POSCAR exactly. Insert: `molecules.dat` format of `insert_umd.py` (`ntime`, `natom`, `element x y z`; `data/molecules.dat`), random reduced position, uniform random orientation (`Rotation.random`) about the centre of mass, no atom closer than `-r` (default 2.0 Å, user's choice) to any other, nearest images, any cell. Checks: intramolecular distances kept to 3e-15 Å in cubic and hexagonal boxes, intermolecular ≥ `-r`, orientations uniform (400 dimers), the snapshot's atoms and velocities unchanged. Former scripts: `box_shuffle.py` imported the removed `umd_process` (could not run), checked distances without periodic images in a cubic cell of side a, retried by reshuffling shuffled positions with no limit and a 0.5 Å threshold, truncated coordinates (`'%.7s' % str(x)`); `insert_umd.py` only handled orthogonal cells (acell), drew rotation axes in the positive octant only (non-uniform orientations), rotated about the first atom, dropped the velocities of the snapshot, gave the new atoms none, named outputs `struct-<n>`; `build_supercell.py` dropped velocities and wrote str() precision. Extract: `--extract <atoms>` (indices/ranges from 0 and element symbols, e.g. `0-9,25`, `O,H`) writes instead the trajectory of the selected atoms, every `-s`-th snapshot (default 1) from `-i` (default 0), to `<name>.<atoms>.umd.dat`, read and written line by line (any file size): atom lines copied as they are, snapshot lines (energies, T, P, cell — of the whole system) kept, timestep × `-s`; replaces `extratom_umd.py` (one atom; dropped the snapshot fields except the cell, rebuilt `time` from 1), removed with `print_atomic_header`/`print_atomic_snapshots` of `umd_processes_fast.py` (and `sort_umd`, used only by `insert_umd.py`). Checks: atom 12 of glycine has the same lines as with `extratom_umd.py` in all 10000 snapshots; the MSD of the extracted O atoms (`msd_umd.py`) equals the O column of the full file exactly.
- `stat-concentrate.py` — concentrates the statistics of independent runs at the same P and T: all the `*.r0.stat.dat` of the current folder (r0 only — the liquid and the vapor are told apart by the size of the r0 clusters, `-l`), one column per run, with the mole and mass liquid/vapor partitioning of the elements of `-c`; the output name records the options (`<-f>all.-t<t>.-L<l>.-R0.-C=<c>.dat`, keep it). `-t`: species whose total time in a run is shorter than t fs are left out of that run (it was read but not used). Unused `relativespecies` removed; outputs unchanged with the defaults.
- `check_umd.py` — quality checks of a run from its UMD file (formerly `check_overlap.py`, the core overlap only), each ending OK / WARNING / skipped, report also in `<base>.check.dat`; one line-by-line pass (fields of every snapshot; atom lines of every `-s`-th from `-i`), ~3 s for glycine (10000 snapshots). File: (1) times — backward, duplicated, gaps, irregular, repeated configurations (a file concatenated with an overlap is caught); (2) unwrapping — between snapshots read, Δ(unwrapped) − Δ(wrapped) in reduced coordinates of the current cell must be whole numbers (valid for NPT; a missed crossing is a whole cell vector, caught by 3; the synthetic `glynpt` file, whose unwrapped positions are those of the undeformed run, is flagged); (3) jumps — displacement between snapshots read > 2 max(|v|) Δt + 0.2 Å (old `al2o3.umd.dat`: 225, up to 9.6 Å). Dynamics: (4) energy drift — slope of `EnergyWithDrift` with the jumps (> 20 × the median change) removed, warning above 1 meV/atom/ps, and the jumps listed (restarts: hydrous andesite every 2000 snapshots; ML learning steps: al2o3, ZnS; unconverged steps: pyrolite); glycine −1.05, pyrolite −8.1, andesite +19 meV/atom/ps; (5) time step — 0.1 Å / median of the largest speed of the fastest element, against the timestep of the file (andesite H at 3000 K: 0.14 Å per 1 fs step); (6) momentum — centre-of-mass velocity and displacement, warning when its squared displacement exceeds 5 % of the end-to-end MSD of the slowest element (old al2o3: 67 % of He); (7) net force — |ΣF|/√N / rms force > 0.02 (all test files ≤ 0.007). Electrons: (12) core overlap with `-r` (lens volume, % of the two spheres, `-l` default 12 %; `<base>.overlap.dat` per snapshot; the former version used acell[0] for the nearest image along every direction, applied the lens formula beyond contact, and flagged every snapshot with overlaps ~10⁹ % when an element had a single atom); (13) |T S_el| from `ElectronicEntropy` > 1 meV/atom. ## Naming Conventions
Output files inherit the UMD filename as prefix: `<base>.umd.dat` → `<base>.gofr.dat`, `<base>.bonding.dat`, `<base>.r0.popul.dat`, etc. Test data in `data/` follows this convention with `glycine.*` files.
