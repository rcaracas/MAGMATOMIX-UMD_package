# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

UMD (Universal Molecular Dynamics) is a Python package for post-processing ab initio and classical molecular dynamics simulations. It works around a central ASCII file format (`.umd.dat`) that stores atomic trajectories and thermodynamic data extracted from simulation codes (VASP, ABINIT, CP2K, QBox, LAMMPS).

## Building C Extensions

Performance-critical routines are implemented as C shared libraries loaded at runtime via `ctypes`. They **must be compiled before running any analysis script**. All commands run from `src/`:

**macOS:**
```bash
gcc -O2 -dynamiclib -o c_UMDprocess.dylib c_UMDprocess.c
gcc -dynamiclib -o c_bonds_full.dylib c_bonds_full.c
gcc -dynamiclib -o c_clusters.dylib c_clusters.c
gcc -O2 -dynamiclib -o c_gofr.dylib c_gofr.c
```

**Linux / Windows (`.so` / `.dll`):** See `compilC-mac.txt` and `compilC-windows.txt` for the analogous commands.

`umd_processes_fast.py` auto-detects the OS and loads the correct library extension (`.dylib` / `.so` / `.dll`). The library path is resolved relative to the script's own `__file__` location, so scripts must be run from the `src/` directory or the libraries must be on the system path.

## Dependencies

```
python3, numpy, scipy, matplotlib
```

No package installation is required — scripts are run directly.

## Running Scripts

All scripts are standalone executables. Typical invocation pattern:
```bash
python3 src/VaspParser.py -f <OUTCAR_file> [-i InitialStep] [-s SkipStep]
python3 src/gofr_umd.py -f <file.umd.dat> [options]
python3 src/averages.py -f <file.umd.dat> [-p Pattern] [-s SkipSteps] [-l] [-v]
```

Use `-h` or read the argument-parsing block at the bottom of each script to discover its options.

## Architecture

### Core Libraries
- **`crystallography.py`** — Defines the two central data structures used everywhere:
  - `Atom`: position (`xred`, `xcart`, `absxcart`), velocities, forces, charge, magnetization
  - `Lattice`: simulation cell (vectors, volume, angles), atom list, and all thermodynamic scalars (energy, pressure, temperature, stress tensor, etc.). Also contains `Elements2rest()` (element → name, symbol, atomic number, mass; None if unknown), `Elements2charge()` (formal charge: the most common oxidation state in oxides and ionic compounds, field `formalcharge` of the table, used by `check_umd.py`) and coordinate-transformation methods: `xred2xcart`/`xcart2xred`/`absxcart2xred` (wrapped into [0,1)) and their `all…` versions over the atoms, xcart = xred @ rprimd with rprimd as it is (rows a, b, c), and `makegprimd` = inverse(rprimd) transposed (xred[i] = Σ_j gprimd[i][j] xcart[j]; `VaspParser.py`, `repair_umd.py`). The conversions summed `rprimd[ii][jj]*xred[ii]` (wrong index: right only for cubic cells; 3.4 Å off in a hexagonal cell) after rebuilding rprimd from acell·rprim; only `QBoxParser.py` used them, so QBox runs in non-cubic cells had wrong coordinates. `makegprimd` printed an error and did not divide by the determinant for left-handed cells (now any handedness; outputs of `VaspParser.py` on ZnS and `repair_umd.py` on hexagonal corundum byte-identical to before). Removed: `compangles`, `printstruct`, `niceprint` (called a missing `cartlatt`), `TripleLattice` (missing `cartatom`), `derive_types_from_typat`, `distance`, `CheckAtoms` (unused). `getdensity` uses the exact Avogadro constant.
  - `Lattice.__init__`'s `acell`/`angles`/`rprim`/`rprimd`/`gprimd`/`stress` used to be mutable default arguments, so every `Lattice()` created without explicit values silently shared (and could corrupt) the same list — fixed to build a fresh list per instance. No script constructs `Lattice()`/`Atom()` with explicit keyword arguments, so this was a pure latent-bug fix.
- **`umd_processes_fast.py`** — Python wrapper around `c_UMDprocess.dylib` (ctypes). Provides fast reading of UMD snapshots and bond-definition routines used by most analysis scripts. This is the main I/O layer for `.umd.dat` files. It holds the only POSCAR routines of the package, and the shared readers/writers `read_snapshots(UMDfile,natom,first,sampling,fields,atoms)` (line by line, any file size: yields the fields of every snapshot and the atom array — reduced, cartesian, unwrapped, velocity, force, charge, magnetization — of every sampling-th from first; used by `check_umd.py` and `umd2out.py`), `missing_umd(name)` (the message of every script taking one UMD file when `-f` is missing or wrong: give it with `-f <file>`, or `-f all`; formerly `umd file   does not exist` with an empty name), `run_on_all(argv,main,paired,single)` (`-f all`: the script's `main` once per `*.umd.dat` of the current folder, sorted, with `-f <file>`; `paired` options taken per file from its base — speciation `-b <base>.bonding.dat`, msd_clusters `-p <base>.r1.popul.dat` —, `single` options refused — `-o` of umd2out and repair_umd —; `SystemExit` and exceptions of one file caught, the next file goes on, the failed ones listed; `headerumd` prints the banner once per process; outputs identical to separate runs, checked on glycine, pyrolite and a 1-snapshot file for check, gofr, bonding, speciation, msd, msd_clusters, viscosity, vibrations, vdos_thermo, umd2out; `averages.py`, `thermo_integration_umd.py`, `umd_workflow.py` take `-f all` as their default), `cell_of(fields)` (rprimd, else acell) and `xyz_frame` (one extended XYZ frame, used by `umd2out.py` and `build_umd.py`). POSCAR: `write_poscar(filename,title,cell,elements,counts,xred,vels=None)` (atoms grouped by element, direct coordinates, `Cartesian` velocities in Å/fs) and `read_poscar(filename)` (VASP5, reduced or Cartesian, selective dynamics, Cartesian velocities; returns title, cell, element per atom, xred, vels or None), used by `build_umd.py` and `umd2out.py`; `crystallography.Lattice.printcontcar` (unused, wrote typat as the atom counts) was removed. `read_values(UMDfile,key,mode,Nsteps,firststep,laststep)` (key xred, xcart, absxcart, velocity, or everything = these 12 columns; snapshots firststep, firststep+Nsteps, … before laststep) reads in one pass in C (`c_UMDprocess.c`: `umd_read`, numbers by strtod) into a numpy array (snapshot, values; `lists` (snapshot, atom, column), `chunks` column after column); Batches for the workers (2026-11-09, the user's aim: systems up to 10⁹ atoms, big snapshots): `index_snapshots(UMDfile,natom)` (C `umd_index`, one pass: the byte offset where each complete snapshot begins — the end of the former one — as int64, and its cell; 0.24 s for andesite), `read_atoms_at(UMDfile,offset,natom,nsnap,sampling,col0,ncol,cells)` (C `umd_read_at`: `umd_read` from an offset; `umd_read` = offset 0; files opened `rb`, 64-bit `fseeko`/`_fseeki64`), `batch_ranges(nitems,bytes_per_item,nworkers)` (consecutive ranges of up to `BATCH_BYTES` = 64 MB of input, one snapshot when it is larger, and at most nitems/(4 nworkers) so every worker gets several tasks), `ordered_map(func,tasks,nworkers)` (process pool, at most 2 tasks per worker submitted, results yielded in task order; 1 worker = in-process, no pool). Used by `bonding_umd.py`, `gofr_umd.py`, `read_bonds` (`read_bonds_batch`: one open per batch) and `speciation_and_angles.py` (clusters, angles, bond codes). Threads around the C reader are slow on macOS (16 threads: 12 s of system time for andesite against 0 in processes; `strtod` on a locale lock, presumably): use processes. `count_snapshots` gives the complete snapshots (a last snapshot cut short, by a run still being written, is left out with a warning) and `read_cells` the cell of each snapshot (rprimd, else acell) from the same C reader. Values identical to the former reader on glycine, ZnS, hydrous andesite, corundum (the files have 5 decimals, which the former reader rounded to); 3–6× faster without child processes (hydrous andesite 468 MB: 0.9 s vs 2.7 s and 9 CPU s in 16 processes), 2.5–3× less memory (compile it with -O2: 1.5× faster). The former reader ran one process per snapshot with a hand-written number parser: `E` exponents, tabs and repeated or leading blanks gave wrong values silently (up to 11 Å), a truncated last snapshot was read as zeros, and it failed when run from standard input (process pool). With Nsteps > 1 it read int(n/Nsteps) snapshots, missing the last one (glycine `-s 3` from 5: 3331 instead of 3332); now all, also in `read_bonds` (bonding files). `Crystallization` (header, also `no.of.electrons` and `lambda_ThermoInt`, and the cell of the first snapshot; stops at the first snapshot, also of a bonding file, which it formerly read to the end) replaces `read_bigheader_umd`; its unused `WithLength` option (time of the last snapshot parsed byte by byte) was removed. `read_stresses_4visc` uses `read_snapshots`. `defineBonds` (C, bonding files) allocated (N_central+N_adjacent)² integers per snapshot (400 MB for 10000 atoms) and its result was never freed. `print_header`/`print_snapshots` (all parsers, `build_umd.py`, `repair_umd.py`) build one string per snapshot (output byte-identical). The library path is built with `os.path` (formerly split on `/`, which fails on Windows).

### UMD File Format (`.umd.dat`)
Human-readable ASCII: one header section per snapshot followed by per-atom lines. Fields include `timestep`, `time`, `InternalEnergy`, `Enthalpy`, `Temperature`, `Pressure`, `StressTensor`, `acell`, `rprim`, and per-atom `xred`/`xcart`/`vels`/`forces`. Parsers write this format; analysis scripts read it.

**Rule: no update or new feature may change the format in a way that breaks the reading of UMD files, by the current or by former versions of the package.** New information goes into new lines that every reader skips: never the first line (old readers take it as `natom`), never between the `atoms:` line and the atom lines, and with no field name as a separate word (`averages.py` greps the fields anywhere in the file).

The header ends with `origin <code> : <sentence>` (`umd_processes_fast.print_header(…,origin)`, read into `Lattice.origin` by `Crystallization`), the code that produced the run: `VaspParser.py` writes `origin VASP : the UMD file originated from a VASP ab initio molecular dynamics simulation`, `LAMMPSParser2umd.py` `origin LAMMPS : …`, `build_umd.py` `origin build_umd.py : the UMD file is a structure built by build_umd.py, <title>`; copied by `build_umd.py --extract`, `repair_umd.py` and into the bonding files. Files written before have no origin line. Checked: the readers of the current and of the former version (before fad7cee) give identical outputs with and without the line.

### Parsers (simulation code → `.umd.dat`)
| Script | Source format |
|---|---|
| `VaspParser.py` | VASP OUTCAR |
| `AbinitParser.py` | ABINIT MD output (layout of 6.4.1) |
| `CP2KParser.py` | CP2K MD files: positions (xyz), velocities, forces, `.ener`, `.stress`, `.cell` |
| `QBoxParser.py` | QBox XML output |
| `LAMMPSParser2umd.py` | LAMMPS dump files (custom/atom or xyz) and log |

`VaspParser.py` unwraps the positions (`absxcart`) at every MD step from `-i` on, even those not written with `-s`, so no crossing of a cell face is missed. It finds each crossing as a whole-number change of the displacement in reduced coordinates, which works for any cell shape. The `timestep` it writes is the time between written snapshots (`-s` × POTIM), as the analysis scripts expect. On-the-fly ML learning steps print the positions twice (ML and DFT blocks); the previous positions are taken only from the first block of each ionic step. `TotalElectronicEnergy` = the free energy TOTEN of the `% ion-electron` line, divided by SCALEE (λ, thermodynamic integration), as in the parser before the ML rewrite (cbc0495, January 2026), which had dropped it (0.0 written in every snapshot since; glycine predates it). So InternalEnergy = TotalElectronicEnergy + ElectronicEntropy (= E0 − TOTEN) + KineticEnergyIons (λ = 1). Checked on the ZnS OUTCAR (ML_ISTART=1, 10000 steps, 57 of them with a DFT calculation): TotalElectronicEnergy = TOTEN in all 10000 steps, the relation within 1e-6 eV, the rest of the UMD file identical to before.

`AbinitParser.py` (options as `VaspParser.py`: `-f`, `-i`, `-s`; output `<file>.umd.dat`): checked on one real run, `data/abinit.exMD.output` (ABINIT 6.4.1, ionmov 9 = Langevin, 40 atoms Mg7Si8O24Fe, spin polarized, non-orthogonal constant cell, 251 steps of 1 fs). Layout: each `MOLDYN STEP NUMBER n` has SCF, stress, then two blocks xcart/xred/fcart/fred/vel, then `At the end of Moldyn step n`. Measured on the file, a trap: the first block holds x(n), F(n) and v(n) (v = 0.507 forward + 0.508 backward difference; POT.En.(n) changes as ∫F·dx along these x); the second block holds x(n+1), the same F(n), and v(n+1) (it is the first block of the next step); the `EKIN` and `KIN+POT.En.` printed at the end of step n are computed with v(n+1), one step off the POT.En. So a snapshot = the first block, with KE = ½Σmv² of its own velocities (= the EKIN of step n−1, 8e-8 eV). Step 0 has v = 0 in its first block (initialized after it), so its velocities are the forward difference from the second block. `TEMP` at the end of a step is the target temperature (ramp mditemp → mdftemp), not the instantaneous one; `TKA` = kinetic T (3N)/target. Temperature = 2 KE/(3N kB), 3N as ABINIT, the COM is not conserved with Langevin (check_umd 9 then reads 1.0256). Stress: ABINIT sigma is positive in tension, printed on two columns `sigma(1 1) sigma(3 2) / sigma(2 2) sigma(3 1) / sigma(3 3) sigma(2 1)`, without kinetic part; UMD = −sigma + Σ m v v / V, positive in compression, as VASP `Total+kin.` (kinetic part 14 GPa here, of 61 GPa); xy yz zx order. POT.En. = free energy Etotal = TotalElectronicEnergy. `-kT*entropy` is printed only at the end of the run (T S 1.75 eV in the last step), so ElectronicEntropy = 0 and InternalEnergy = free energy + KE. EnergyWithDrift = InternalEnergy (no thermostat energy in the output). Enthalpy = InternalEnergy + P V. Magnetization = `magn` column of the last ETOT line; no per-atom charge or magnetization per step. xcart of ABINIT is not wrapped: xred wrapped into [0,1), xcart = xred·rprimd, the unwrapped column followed by nearest image from step `-i` on. Atoms grouped by type, stable, in znucl order (ABINIT keeps the input order). Masses `amu`, cell `R(1..3)`, zelec the zion of the pseudopotentials, no.of.electrons Σ zion − `charge`. Refused before writing anything: several datasets (`ndtset`), `optcell` ≠ 0, no `MOLDYN STEP NUMBER` line (newer ABINIT prints MD differently: no example yet); warning for ionmov ≠ 9, unconverged SCF, missing stress (StressTensor 0), kinetic T more than 10 % off the target. Only complete steps are written (cut files give the steps before the cut). Checks: an independent script reading the raw file gives every value to the rounding of the UMD file (cell volume, positions, forces, velocities, energies, T, P, stress); static P at the last step 55.9242 vs 55.924 printed by ABINIT and xy yz zx −3.856 −2.493 −8.854; velocities integrated in time follow the unwrapped positions (rms 0.0018 Å over a 0.59 Å displacement); `-i 10 -s 3` equal to the matching snapshots of the full file; check_umd, gofr, analyze_gofr, bonding, speciation, msd, viscosity, vibrations, vdos_thermo, averages, umd2out all run; readers of 2.7 and fad7cee read it (averages identical). ### Analysis Scripts
Each script imports `crystallography` and `umd_processes_fast`; most also load a dedicated C library for the heavy computation.

**Structural:**
- `gofr_umd.py` — pair distribution functions g(r) and running coordination numbers `Int(A-B)` of all element pairs, one method for every cell (uses `c_gofr`, compiled with -O2: ~25 % faster). The C routine takes the nearest image in reduced coordinates (ds − rint(ds)), exact up to half the smallest distance between opposite faces of the cell (V/|b×c| etc.), the largest r computed; it uses the cell of every snapshot (NPT; read from the rprimd lines, matched to read_values' -i/-s selection) and fills caller-allocated histograms over blocks of snapshots (`np.array_split` in `-k` blocks, as before) run in processes (`ordered_map`; threads until 2.13: the C reader in threads spent 12 s on a system lock), each block read from the file by `read_atoms_at` in batches of `BATCH_BYTES` and added into the same arrays, so the sums are in the same order: outputs identical to 2.13 for the same `-k` (andesite 1.65 → 1.0 s, 307 → 65 MB). g is normalized with the volume of each snapshot and N_i(N_j − δ_ij) pairs, so it tends to 1; `-c` central / `-a` adjacent elements (commas, default `all`): the pairs central–adjacent and their reverse are computed (as `analyze_gofr.py -c/-a`; `-c O` = O-X and X-O for every X), only the atoms of these elements in the computation; all the pairs of the UMD file are written, in its order, the others with g = 0 and Int = 0, so `analyze_gofr.py` writes them with 0 (no bond) in complete `.inp` files (it writes every pair of the elements of the gofr file, also for a file of 2.8.2 with only the selected columns: then the pairs of its elements only) and leaves them out of its plots (the user's choice, 2026-10-26; in 2.8.2 the file had only the central–adjacent columns); output `<base>.<central>-<adjacent>.gofr.dat` (symbols concatenated, `all` when not given, e.g. `.SiMg-O.`, `.O-all.`; without `-c`/`-a` `<base>.gofr.dat` as before, byte-identical); `bonding_umd.py` with the resulting cutoffs bonds only those pairs (pyrolite `-c Si,Mg -a O`: Mg-O and Si-O bonds only); columns identical to those of the full file (same `-k`: the threads sum in a different order otherwise, last digit), `analyze_gofr.py` gives the same cutoffs and coordinations (pyrolite Si-O, Mg-O); Int = cumulated pair counts / N_i, up to the outer edge of each bin. Output format unchanged (header parsed by `analyze_gofr.py`). It replaced `c_gofr_new_alt`, which wrapped the b direction with the a component in non-orthogonal cells, normalized with maxlength³ instead of the volume, took the largest r from vector lengths (and ignored c in orthogonal cells), used one cell for all snapshots, and ignored -k. Checks: ideal gas in a triclinic cell changing at every snapshot gives g = 1.000 ± 0.03; fcc in its cubic and its 60° primitive cell give the same 12 and 54 neighbours; hexagonal corundum equals a brute-force count over explicit images to 3e-14; cubic pyrolite equals the old code for unlike pairs (3e-13) and differs by N/(N−1) for like pairs; 0.9 s vs 4.2 s. `gofr_new_notcubic.py` and `c_gofr_new.c` (a never-compiled duplicate) were removed.
- `analyze_gofr.py` — first maximum, first minimum, coordination number and mean distance (∫r³g/∫r²g up to the minimum) of the first shell of every pair, from the gofr files of `gofr_umd.py`; automatic, `-v` to check and correct each pair in a plot. Merges the former `analyze_gofr.py` (clicks on every pair of every file), `analyze_gofr_semi_automatic.py` (clicks on the first file, guesses for the others) and `analyze_1gofr.py` (one file, mean distance), all removed. Method: g smoothed by a gaussian (`-g`, default 0.03 Å; 0.05 loses the small O-O peak at 2.5 Å of glycine); the first peak is the first one with g > 1 whose prominence exceeds 10× the local noise of the smoothed curve (MAD of the second differences over ±25 bins, robust to the curvature of sharp peaks; a residual-based rms was inflated near sharp peaks and hid the glycine O-O sub-peak); the minimum is the lowest point before the next prominent peak (any height: the N-H sub-peak at 1.68 Å of glycine, g 0.43, bounds its first minimum). Maximum: cubic fitted to g over the top quarter of the peak; minimum: cubic over the bottom tenth of the dip (`MAX_FIT`: both fits at most 1 Å wide, ±0.5 Å around the extremum of the smoothed g; the user's choice), else the lowest point of the smoothed g when the cubic has no minimum inside; when g = 0 at the minimum (between the shells of a molecule) the middle of the run of g = 0 bins (any cutoff inside gives the same bonds; glycine C-C 2.320 Å, gap 1.705–2.935 Å; 1.665 Å in the first version, 14924 vs 14920 C-C bonds over 1000 snapshots). Until 2026-10-26 the minimum was a parabola over the whole bottom tenth (up to 2.1 Å wide), biased toward the slow side of asymmetric dips: pyrolite Al-O 2.721 Å vs 2.575 for the lowest point of the smoothed g (now 2.600), Mg-O 3.035/2.965 (2.979), Si-O 2.599/2.475 (2.420, a flat dip), hydrous andesite H-O 1.392/1.475 (1.511), glycine N-H 1.433/1.335 (1.351); coordinations Si-O 4.056 → 4.004, Al-O 4.185 → 4.087, Mg-O 5.076 → 4.929, H-O 1.025 → 1.058; the maxima are unchanged (their windows are 0.06–0.7 Å). Coordination = Int(A-B) interpolated at the minimum on the outer bin edges. A-B and B-A share positions, each its own coordination. Terminal table: printed once (after the checks with `-v`), one line per pair A-B with the coordination numbers of A-B and B-A, the pairs not analyzed or without pairs on one line. Notes: `shallow minimum` (g(min) > 0.5 g(max)), `no pairs`, `no peak above the noise and above 1`, `no minimum up to rmax`. The noise of minority pairs (1–3 atoms of an element) is correlated between bins (slow configurations), so noise bumps of 5–20× the white-noise estimate occur there and their positions are unreliable (e.g. pyrolite Na-*, Al-Al): check them with `-v`. `-v`: buttons Discard, Automatic, Manual, Previous, Next (one pass over the pairs of all files, each pair once — A-B and B-A share the g(r) and change together —; Next on the last pair closes the window and writes the files, Previous on the first stays; no wrap-around); two left clicks, the maximum then the minimum (the right click of the former version, for the minimum, did not reach matplotlib on Mac trackpads); the clicks are fitted (note `clicked, fitted`): from each click up (down) the smoothed g to the top of its peak (bottom of its dip), then the fits of the automatic analysis (cubics over the top quarter and the bottom tenth, at most 1 Å), so a click on an automatic shell gives its values back (pyrolite: exactly for the main pairs, ≤ 0.03 Å for noisy minority pairs, where a click lands on a neighbouring wiggle); Manual: a switch, highlighted while on (kept across pairs), the clicked points as they are (maximum height = clicked height; note `manual`) — until 2.9.1 two buttons, Manual input (the default fitted clicks) and All manual, merged at the user's request; a minimum before the maximum is refused; the files are written when the window is closed. - `thermo_integration_umd.py` — free energy and entropy by thermodynamic integration from the ideal gas to the ab initio system (VASP SCALEE = λ): F = F_ideal gas + ∫₀¹⟨U⟩_λ dλ, S = (E − F)/T. - `vdos_thermo.py` — harmonic thermodynamics from the vDOS of `vibrations_umd.py` (reads `<base>.vibr.err.dat`, else `<base>.vibr.dat` without errors; atom counts from the UMD header; each element renormalized to 3 N_El modes): per atom and per element, quantum ZPE, E, F, S, Cv, and the quantum corrections dE, dF, dS, dCv = quantum − classical harmonic (Berens et al. 1983), to add to classical MD values; `-t T1,T2,…` (default: the vDOS temperature; the MD frequencies are kept). The Lorentzian (1/ν²) exceeds the vDOS at high ν, making the solid-like vDOS negative (column `negative`, 0.3–2 %): negligible for the quantum S_2PT, but it gave wrong-sign classical S_2PT and solid-part quantum corrections, so these were removed; dE etc. come from the whole vDOS. - `vibrations_umd.py` — velocity autocorrelation functions (VACF), vibrational densities of states (vDOS) and diffusion coefficients from the UMD velocities, per element and, with `-a cart` / `-a cryst` / `-a [x1,y1,z1,...]` (as in `msd_umd.py`), per element along each axis (not per atom). The only vibration tool: it replaced `vibr_spectrum_umd_fast.py` (its C library `c_autocorrelation_vib`, O(N²), took ~10x more CPU time), `spectra_umd.py` (broken with current scipy) and `spectra_umd_corrected.py`, all removed. VACFs by FFT over all time origins. vDOS = 2 m/(kB T) × the cosine transform of the VACF, mass-weighted, in states per cm⁻¹ (the old script wrote per fs⁻¹ against a cm⁻¹ axis), so the vDOS of an element integrates to 3 N_El · T_kin/T (N_El per axis). With `-i 0` the first snapshot is dropped when its ⟨v²⟩ is 0 or more than 10× from the median of the next 100: the parsers have no previous step there (current `VaspParser.py` writes 0; older versions wrote the positions, as in the pyrolite and glycine test files, which gave a spike at t=0 in the VACF and a flat vDOS up to Nyquist). `-w` is the VACF length used for the spectra (steps, default half a block, max half the run), `-p hann` (default) / `none` a one-sided Hann taper applied to all spectra (suppresses truncation ringing), `-g` a Gaussian smoothing in cm⁻¹ (reflection at 0, exact for an even spectrum), zero-padding ×4 for a finer frequency grid. D (Green–Kubo) is the running integral 1/3∫⟨v(0)·v(t)⟩ (∫⟨v_k v_k⟩ per axis), read at `-e` (steps; default and max half a block), with the standard error over `-n` blocks (default 4, min 3), and a warning when D changes by > 2 errors between half the integral and its end (solids: D oscillates around 0, which the block error does not include). Checks: the MSD of `msd_umd.py` equals 2∫∫VACF within 1 % up to 1 ps on the hydrous andesite; synthetic OU velocities give unbiased D with error/scatter 0.98–1.03; synthetic oscillators give the right peaks and exact normalization. ## Naming Conventions
Output files inherit the UMD filename as prefix: `<base>.umd.dat` → `<base>.gofr.dat`, `<base>.bonding.dat`, `<base>.r0.popul.dat`, etc. Test data in `data/` follows this convention with `glycine.*` files.
